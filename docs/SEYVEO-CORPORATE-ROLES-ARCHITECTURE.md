# SEYVEO · Корпоративные роли и единая Сэйви

**Дата архитектурного решения:** 28.10.2026. **Статус:** спецификация для реализации, а не запущенная корпоративная система.

**Связь с утверждёнными решениями:** [продуктовая концепция](SEYVEO-PRODUCT-CONCEPT.md), [наставник новичка](SEYVEO-EMPLOYEE-ONBOARDING.md), [единая карта идей](SEYVEO-IDEAS-MASTER.md), [нативный Personal Core](SEYVEO-MOBILE-PERSONAL-CORE.md). Этот документ **не создаёт второго банка идей**, не отменяет решений 22–27 октября и не означает наличие реального сервера, корпоративной подписки или работающего чата.

## 1. Главное решение: одно установленное приложение, несколько пространств и ролей

SEYVEO на iOS и Android — **одно нативное приложение, одна знакомая Сэйви и один визуальный язык Black Velvet / White Velvet**. Не выпускать без отдельной необходимости урезанный клиент для сотрудника, отдельную «Сэйви-директора» или новую независимую идентичность помощника.

- **«Мой мир»** — личные дела, здоровье, забота, семья, заметки, личные документы, собственные контакты, музыка и SEYVEO Play. Личные данные не становятся корпоративными при вступлении в компанию.
- **«Моя работа»** — видимый сотруднику контекст выбранной компании: его задания, коллеги по разрешённым каналам, инструкции, сообщения, вложения, смены и подтверждённые достижения. Раздел появляется только при активном рабочем членстве.
- **«Пульт бизнеса»** — набор управленческих функций для директора и уполномоченных руководителей: подразделения, права, очереди задач, исключения, контроль результата. На управленческих ролях находится в «Управлении»; сотруднику без полномочий **не показывать пустой пульт или запрещённые пункты**.
- **«Мой бизнес»** — собственная карточка организации, QR, сведения и связанные инструменты. Не дублировать под этим именем чужую компанию в личном профиле сотрудника.
- **Главная Сэйви и сфера** остаются едиными. Информация из «Моего мира» и «Моей работы» показывается с понятным происхождением, приоритетом и границей прав. Не добавлять второй док, шар или параллельную систему карточек.

**Коммерческое различие и корпоративный доступ — разные оси:**
SEYVEO ONE предназначен для частной жизни; SEYVEO RISE — для создания и развития бизнеса; SEYVEO AUTONOM — для расширенной автоматизации и организации команд. AUTONOM Enterprise — масштаб корпоративного внедрения по договору, а не четвёртый тариф. У пользователя может быть личный профиль без личной платной ONE и одновременно право на рабочее место, оплаченное компанией. Условленные компанией личные функции доступны только в пределах её лицензии и применимых прав третьих сервисов, без обещания доступа к чужим музыкальным каталогам.

## 2. Одна личность человека, отдельное членство в компании

**Сущности (планируемые, сейчас в коде нет):**

| Сущность | Владелец | Смысл |
|---|---|---|
| `PersonalAccount` и `PersonalVault` | Человек | Личная Сэйви, личная память/настройки/данные, отдельные ключи и резервное копирование |
| `Organization` | Компания | Юрлицо/компания, правила хранения, платёжный договор, разрешённые интеграции |
| `Membership` | Компания + подтверждение человека | Связь пользователя с организацией: состояние, филиалы, роли, сроки, видимая политика |
| `RoleAssignment` | Уполномоченный администратор | Конкретные права в одной организации, при необходимости в определённом филиале |
| `Workspace` / `Branch` | Компания | Подразделение, магазин, склад, проект и его разрешённые каналы |
| `WorkTask` / `WorkMessage` / `WorkFile` | Компания | Отдельные серверные рабочие объекты, назначения, файлы, истории и сроки хранения |
| `Entitlement` | Выдавшая сторона | Личное право ONE и/или право от корпоративного места с датой отзыва; **не роль** |
| `AuditEvent` | Компания по договору | Записи о корпоративных действиях и доступе ИИ, без личных бесед и истории досуга |

Идентификатор человека не равен ID рабочего места. Одна учётная запись может быть сотрудником компании А, подрядчиком компании Б и владельцем своего дела В, но **рабочие хранилища и права организаций полностью изолированы**. Каждое действие содержит `organization_id` и, где нужно, `branch_id` — доверять этому значению с клиента без серверной проверки запрещено.

## 3. Матрица ролей, а не отдельные приложения

Роли — пример стартового набора; права задаются явно, сочетания возможны только по разрешённым правилам.

| Возможность | Директор | Управляющий филиалом | Работник | Склад / логистика |
|---|---|---|---|---|
| Мои рабочие чаты, задачи и файлы | По назначенным правам | По назначенным правам | Свои / доступные каналы | Свои / доступные каналы |
| Общая управленческая сводка | По разрешённым компаниям | Свой регион / филиал | Нет | Нет |
| Назначить поручение | По полномочиям | В пределах команды | Только разрешённый запрос / передача | В пределах назначенного процесса |
| Управлять участниками и ролями | Собственник / назначенный админ | Только если делегировано | Нет | Нет |
| Согласование документов, финансов и платежей | По отдельным полномочиям | По отдельным полномочиям | Нет | По отдельным полномочиям |
| Личные чаты, личное здоровье, музыка, планы карьеры другого человека | **Нет** | **Нет** | **Нет** | **Нет** |

**Никто, включая директора, не получает личную информацию сотрудника по умолчанию.** Руководитель видит только разрешённые рабочие статусы. Корпоративные переписки обрабатываются согласно явно опубликованной политике компании; не обещать одновременно сквозное шифрование и скрытый серверный просмотр всех сообщений. Права проверяются на **каждом** запросе к API, документу, медиа, поиску и инструменту Сэйви; скрытие кнопки не является защитой.

## 4. Жизненный цикл подключения сотрудника

1. Руководитель или администратор покупает/оформляет **корпоративный пакет**, создаёт организацию, выбирает лимиты рабочих мест и настраивает роли; это не индивидуальная подписка для каждого работника.
2. Администратор выдаёт **одноразовое или ограниченное по сроку приглашение** по QR/ссылке на конкретный филиал и роль. QR не содержит паролей или прямого доступа к данным. Приглашение должно быть отзывным.
3. Человек устанавливает **обычный SEYVEO**, входит в **свою личную учётную запись** или создаёт её, просматривает компанию, роль, правила использования, права и принимает приглашение. Никакой автоматической передачи личного хранилища работодателю.
4. Сервер создаёт `Membership` в состоянии `active`; Сэйви показывает вход «Моя работа», а соответствующую управленческую функциональность — только по правам. Личные разделы остаются прежними.
5. В первый день Сэйви показывает разрешённые инструкции и наставника. Сотрудник делает работу через понятные действия «Сообщить / Сфотографировать / Поручения / Готово». Рабочее общение поддерживает текст, фото, документы, голосовые сообщения позднее — только после безопасной серверной реализации.
6. При смене роли, филиала или компании права и ключи пересчитываются на сервере; доступные данные на устройстве обновляются, чужие рабочие кеши удаляются.
7. При увольнении или отзыве приглашения `Membership` становится `revoked`; рабочие токены перестают действовать на сервере, рабочие локальные кеши и ключи изолируются/очищаются, после восстановления сети сверяется отзыв. **Личные** записи и Сэйви сохраняются. Разрешённые достижения экспортируются человеком отдельно, не вся кадровая карточка.
8. Если корпоративное место включало временные личные возможности, прекращается только это право. Можно предложить самостоятельную ONE **без автоматического платежа и без удержания личных данных**.

Отдельные сценарии: повторный приём, несколько компаний, потеря телефона, смена устройства, заблокированное приглашение, офлайн при отозванном доступе и восстановление без утечки. При офлайн-работе не позволять бесконтрольно продолжать опасные операции на давно отозванных правах; ограничивать время жизни рабочих допусков.

## 5. Рабочие процессы важнее чата

Корпоративный чат — **канал коммуникации**, не конечный продукт. Сэйви превращает подтверждённое сообщение в структурированную задачу и доводит её до реального результата по правилам компании:

`сообщение / фото → уточнение → назначение ответственного → исполнение → проверка результата → закрытие / эскалация`

Пример: продавец сообщил об отсутствии кассовой ленты → формируется заявка с магазином, количеством и приоритетом → назначенный склад подтверждает выдачу → магазин отмечает получение → директор видит сводку исключений, не сотни сообщений. Сэйви отвечает и анализирует **только данные с разрешением**; не ставит выдуманных диагнозов бизнесу и не подменяет человека при финансовых, трудовых и юридически значимых решениях.

## 6. Технические границы

- **Личное:** нативный Personal Core (локальное шифрованное хранилище/файлы, системная защита ключей, личные копии по согласию). Компания не может принудительно включить загрузку личных сведений.
- **Рабочее:** серверная изоляция организаций, подтверждённая аутентификация, MFA для управленцев, RBAC/ABAC (роль, филиал, конкретный объект), RLS или эквивалентная проверка в API, защита файлов, короткоживущие токены, аудит, политика хранения, резервирование. Нужна отдельная модель угроз и юридическая проверка требований РФ/целевых рынков.
- **На телефоне:** рабочие кеши отдельно от `PersonalVault`; версионированная синхронизация, обработка конфликтов и отзыв доступа, безопасный просмотр документов; отсутствие сети явно показывать. Не считать обычный `localStorage` или скрытую вкладку шифрованием.
- **Сэйви/ИИ:** перед каждым чтением или инструментом сервер заново проверяет полномочия; поиск документов применяет фильтры до извлечения текста; системные события и команды ведут журнал; отправка писем, денег, документов и подтверждения остаются у уполномоченного человека.
- **Подписки и развёртывание:** один корпоративный договор/пакет рабочих мест, возможность расширения и отдельная стоимость enterprise-внедрения; цены, SLA и безопасный хостинг утверждаются позже. Демо не должно показывать фиктивно активированные рабочие места или отправленные файлы.

## 7. Очередность разработки и критерии проверки

1. **Сейчас — документация и навигация:** единая карта идей остаётся одна; в «Управлении» прямой вход в «Наши идеи», рядом существующие «Пульт бизнеса» и «Мой бизнес». Упорядочить названия и не переносить код личной сферы.
2. **Модель данных и безопасность:** протокол личного аккаунта, членства, компании/филиала, матрица прав, статусы приглашения, отзыв доступа, условия использования и модель угроз. Сначала отрицательные тесты на доступ к чужим компаниям и личным записям.
3. **Первый серверный вертикальный сценарий:** 1 организация, 1 управляющий, 2 сотрудника; вход, приглашение, один чат/файл, одна задача, подтверждение, выход и отзыв. Проверить **доставку на двух реальных телефонах** и изоляцию данных.
4. **Рабочая Сэйви:** инструкции и наставник только из разрешённых источников, версии документов и ссылки, эскалация человеку при недостатке знаний.
5. **Корпоративное масштабирование:** несколько филиалов, склад/логистика, роли и отчёты, аудит, нагрузочные испытания, восстановление, защита персональных данных, эксплуатационные расходы.
6. **Нативная приёмка:** iPhone и Android; Black Velvet/White Velvet, клавиатура, вырез камеры, жесты, батарея, работа при плохой сети и смене роли без потери личной базы.

**Запрещённые ложные статусы:** текущий «Пульт бизнеса» в `index.html` и `assets/seyveo-business-command.js` — **только локальный UI-прототип**: текст хранится в браузере, вложения лишь выбираются для предпросмотра, никакие сотрудники не подключаются. `mobile/` — отдельная ранняя нативная основа. Наличие этой спецификации не запускает сервер и не доказывает сквозное шифрование.

**Незыблемые UX-правила:** Главная, сфера, утверждённые карточки Quiet Cinema, существующий док, плеер и личный «Мой мир» не переделываются при добавлении ролей. Новые сценарии включаются только через понятный контекст и серверные полномочия, без дублирования функций и второй Главной.
