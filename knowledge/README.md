# SEYVEO Knowledge Engine · библиотека знаний

Сэйви не должна учить слова по одному или «впитывать весь интернет» без проверки.
Рабочая схема: **языковая модель → поиск нужной информации → ответ с источниками** (RAG).

## Что уже есть

- `knowledge/approved/` — проверенные локальные материалы, которые разрешено использовать для ответов.
- `server/knowledge-engine.mjs` — поиск подходящих отрывков с указанием источника.
- `server/knowledge-intake.mjs` — очередь новой информации и отдельное ручное одобрение.
- `server/intelligence/research-planner.mjs` — определяет тип публичного вопроса, формирует запрос и проверяет разнообразие результатов.
- `server/live-search.mjs` — внешний поиск по запросу с согласия пользователя, только при подключённом провайдере.

## Как добавить новый материал (на компьютере разработчика)

1. Создать файл `knowledge/inbox/topic.json` в UTF-8. Не включать пароли, личные чаты, клиентские базы или чужие секретные документы.
2. Записать настоящий источник и исходный текст, не выдавать собственный пересказ за официальную публикацию.
3. Выполнить `node server/knowledge-intake.mjs scan` из корня проекта.
4. Изучить кандидат в `knowledge/review/`, проверить факты, права, дату и источник.
5. Только после проверки выполнить `node server/knowledge-intake.mjs approve ID` — точный ID указан в файле review.
6. После одобрения материал попадает в `knowledge/approved/`; локальная Сэйви подбирает его фрагменты при ответе, если тема совпадает.

Пример формы (демонстрационный текст, не готовое знание):

```json
{
  "topic": "technology",
  "title": "Проверка технических заявлений",
  "source": "Указать реально прочитанную публикацию и её адрес",
  "text": "Здесь должен быть проверенный фактический материал длиной не меньше шестидесяти символов. Уточняйте даты, условия испытаний и ограничения, отделяя демонстрацию от планов."
}
```

Допустимые темы: `business`, `legal`, `psychology`, `science`, `technology`, `history`, `travel`, `reference`.

## Ограничения и правила

- **Интернет-поиск не равен обучению модели.** Внешние результаты показываются временно, не складываются автоматически в библиотеку и не становятся параметрами модели.
- **Личная память отдельно.** Общие знания не должны получать персональные данные из чата.
- **Ссылки и заголовки ещё не доказывают факт.** Для настоящей проверки нужны сопоставление первоисточников, даты событий и контекст. Планировщик пока лишь формирует план и группы результатов.
- **Надёжность не определяется расширением сайта.** Даже официальный источник не гарантирует независимую оценку собственных обещаний.
- **Не копировать массово чужие материалы** без лицензии; ограничиваться разрешёнными выдержками и ссылками. Условия хранения результатов Brave Search проверять для своего тарифа.
- **Для коммерческого продукта** потребуется реальная оценка качества ответов, контроль доступа к документам и безопасный источник генерации, а не только поиск по ключевым словам.

Это первый этап. Векторный или гибридный семантический поиск, автоматическое обновление из одобренных источников с ревью и ИИ-синтез с цитатами — следующие независимые этапы.
