# SEYVEO Intelligence · Hybrid Core

## Частное подключение настоящего Феликса к iPhone (подготовлено)

Подготовлен закрытый HTTPS-маршрут через Tailscale Serve, **не** через Funnel: iPhone → HTTPS tailnet → loopback-шлюз на 127.0.0.1:8791 → существующая настоящая Главная SEYVEO с Ollama на 127.0.0.1:8790. Это не новая тестовая страница, а исходный index.html приложения, но **на отдельном частном адресе**, а не публичном GitHub Pages. Физическое соединение с iPhone ещё не проверено.

Новые файлы: server/iphone-private-gateway.mjs, server/start-felix-iphone-private.cmd, server/tests/iphone-private-gateway.test.mjs и инструкция docs/SEYVEO-IPHONE-PRIVATE.md. Шлюз требует точный домен *.ts.net и логин владельца из Tailscale Serve, проверяет адрес/источник/маршруты, не хранит секреты в браузере и не позволяет открывать папку server. Node слушает только loopback. Для теста: node --test server/tests/iphone-private-gateway.test.mjs.

**Не включать Funnel, не пробрасывать порты на роутере, не выдавать этот этап за публичный production-сервис.** Подробная инструкция: [SEYVEO-IPHONE-PRIVATE.md](../docs/SEYVEO-IPHONE-PRIVATE.md).

Подготовлено **собственное серверное ядро** SEYVEO. Владелец установил `qwen3:4b-instruct` в Ollama на Windows и получил настоящий локальный ответ; **подключение нового кода на его ПК ещё не проверено**. Облачный GPT-6 по-прежнему не подключён.

- `hybrid-core.mjs`: локальный / облачный маршрут и защита.
- `providers.mjs`: собственная Ollama / OpenAI GPT-6 Responses API.
- `brain.mjs`: единый ответ без изменения данных.
- `chat-local.mjs` и `start-felix-local.cmd`: локальный чат SEYVEO на Windows через Ollama без облака, требуется Node.js 22+.
- `http.mjs`: приватный сервер только на 127.0.0.1; токен обязателен.
- `tests/core.test.mjs`: проверки маршрутов без реальных запросов к ИИ.

Документация: [SEYVEO-HYBRID-CORE.md](../docs/SEYVEO-HYBRID-CORE.md).

Проверка: `node --test server/tests/*.test.mjs` из корня репозитория.

**Не открывать порт в интернет; не вставлять API-ключ в PWA или репозиторий.**

## Феликс через браузер на компьютере

Владелец уже подтвердил установку Node.js 24, Ollama 0.40.6 и модели `qwen3:4b-instruct`. Для **отдельного безопасного теста в браузере**, после получения свежего ZIP репозитория и распаковки, дважды нажми в папке `server` файл `start-felix-browser.cmd`. В Chrome или другом браузере на этом же компьютере открой `http://127.0.0.1:8788/`.

- Файлы: `browser-local.mjs`, `start-felix-browser.cmd`, `local-web/index.html`, `local-web/app.js`, `local-web/style.css`.
- Сервер доступен **только** на локальном интерфейсе `127.0.0.1`, проверяет заголовки Origin и Host, включает CSP и не разрешает облако даже при существующем ключе.
- Через форму обрабатывается **только один текущий вопрос**, история видна на странице, но не хранится и не используется моделью как память.
- Никаких личных файлов, заметок, почты, контактов или календаря. Никаких реально исполняемых действий.
- Для выхода закрой чёрное окно сервера или нажми `Ctrl+C`; сам Ollama можно оставить работать.
- Это не публичное PWA и **пока не открывается с iPhone**. Не настраивай проброс портов на роутере.

## Настоящая Главная с Qwen3 — без изменения опубликованного сайта

Новый локальный запуск: `server/start-real-seyveo.cmd`. На Windows после получения новой копии GitHub ZIP распаковать и запустить этот файл из папки server, затем на том же ПК открыть `http://127.0.0.1:8790/`. Программа Node.js 24 уже установлена, а Qwen3 4B загружена в Ollama на компьютере владельца.

Локальный сервер **отдаёт реальный `index.html` и существующие `assets/` без пересборки интерфейса**, подменяя в передаваемой браузеру копии только последний демонстрационный ответ стандартного поля «Спросить»: он обращается к локальному Qwen3 и показывает результат в той же `orb-inline-reply` под **оригинальной** стеклянной плазмой. Режим заметок, локальные переходы в разделы и отдельные сценарии сохраняют прежние обработчики. Отдельный браузерный прототип на порту 8788 больше не нужен.

Публичная Главная и её JavaScript в GitHub остаются нетронутыми. Локальный адрес имеет **отдельное хранилище браузера** от GitHub Pages, поэтому ранее сохранённые заметки и настройки на публичном сайте не появятся в этой копии и не удалятся на оригинальном адресе. Локальная копия может сохранять собственные демо-настройки в отдельном localStorage; история отправляемых ИИ вопросов через этот мост намеренно не сохраняется.

Защита: порт 8790 открыт только на `127.0.0.1`, проверяются Host/Origin, CSP запрещает внешние подключения, облако принудительно выключено, разрешены только файлы опубликованных assets, никакого доступа к папке `server` или ключам. Service Worker отключён в этой локальной копии. **Не открывать порты 8790 или 11434 наружу или в роутере.** iPhone/публичный GitHub Pages пока НЕ подключены; для этого потребуется отдельная система аккаунтов и защищённая серверная инфраструктура.

Ограничения: это первый разработческий тест, без полноценной памяти и без реальных действий. Он использует существующие обработчики приложения и не превращает все экранные сценарии в ИИ-команды. После запуска проверь на ПК: нажать центральную кнопку помощника → ввести свободный вопрос без команды навигации → «Спросить» → получить ответ от Qwen3 под настоящей плазмой. Останавливается Ctrl+C в чёрном окне.

## 19 октября 2026 · потоковые ответы на настоящей Главной

Оригинальный `index.html` и SVG плазмы **не изменялись**. Локальный сервер `server/real-app-local.mjs`, запущенный `start-real-seyveo.cmd` на `http://127.0.0.1:8790/`, подменяет только последнюю ветку демонстрационного свободного вопроса в отданной браузеру копии Главной.

Теперь поле «Спросить» читает NDJSON с `POST /api/seyveo-stream`: Ollama вызывается с `stream:true`, каждый кусочек ответа отображается **сразу** в существующем `orbInlineReplyText` под фирменной плазмой. Ошибки и прерванный поток объясняются пользователю; браузер не показывает команды модели и не исполняет её действия. Ранее работавший обычный JSON-метод оставлен для совместимости.

Локальный процессор i5-12600K: стартовые параметры `num_thread:8` (можно переопределить `SEYVEO_LOCAL_THREADS` от 2 до 16), `num_ctx:2048`, `temperature:0.5`, `keep_alive:15m`. Ограничение генерации адаптивное: 110 токенов для явно короткого ответа, 150 для простого вопроса, 200 для обычного и 320 для расширенной бизнес-задачи. Это уменьшает избыточный текст и задержку полного ответа; не гарантирует определённой скорости. Первая загрузка модели всё ещё может быть медленнее. На ПК можно сравнить время и нагрузку, после чего менять число потоков.

Все запросы строго на `127.0.0.1`: браузер не отправляет текст в OpenAI, сервер принудительно отключает облако. Новая функция ничего не записывает в заметки, историю или почту, не читает их и не выполняет действия. Для остановки `Ctrl+C` в окне локального сервера. Не открывать на роутере порты 8790 и 11434; iPhone не подключён.

## Локальная память Феликса (ручная, под контролем владельца)

В той же настоящей Главной `http://127.0.0.1:8790/`, в режиме **Спросить**:

- `Запомни: Наша цель — найти первых трёх клиентов SEYVEO.` — показывает подтверждение и только после согласия сохраняет короткий факт (не более 180 символов).
- `Память` или `Что ты помнишь?` — показывает нумерованный список сохранённого.
- `Забудь 1` — спрашивает подтверждение и удаляет запись №1 из актуального списка.
- `Очисти память` — после отдельного подтверждения удаляет все заметки.

Сохранённые факты (до 24 записей) передаются **только локальной Qwen3 через Ollama** как справочные сведения для ответа. Обычные вопросы, ответы, переписка, контакты, календарь и заметки сами собой в эту память **не попадают**. Режим «Блокнот» остаётся самостоятельным и не превращается в команды памяти.

Файл хранится **вне репозитория/ZIP** в профиле Windows: `%LOCALAPPDATA%\SEYVEO\felix-memory.json`. Поэтому обновление ZIP не стирает память; однако перенос на другой ПК потребует отдельного переноса файла. Для текущего прототипа память рассчитана на **одного пользователя Windows**: нет отдельных аккаунтов SEYVEO и синхронизации. Файл JSON **не зашифрован**, поэтому не сохраняйте пароли, API-ключи, банковскую, медицинскую или другую особо личную информацию. Часть таких записей блокируется автоматически, но фильтр не заменяет шифрование. Важно иметь отдельную резервную копию перед полной переустановкой Windows. GitHub, GPT-6 и сторонние сервисы память не получают.

Для запуска после обновления снова откройте файл `server/start-real-seyveo.cmd`. Публичный `index.html` и оригинальная плазма не меняются: команда памяти добавляется сервером только в локально отданную копию главной, до маршрутизатора заметок. Локальный тест запускается только на `127.0.0.1`; не пробрасывайте порты маршрутизатора.

## Настоящий диалог вместо одного вопроса (локальный режим)

В `http://127.0.0.1:8790/` теперь можно продолжать предыдущую мысль: каждое свободное текстовое обращение через кнопку помощника записывается **во временную историю открытой вкладки**, и Феликс получает до трёх последних пар вопрос/ответ (с ограничением объёма текста для скорости на i5-12600K). Под стеклянной плазмой отображаются последние шесть пар разговора в существующей карточке с невидимой полосой прокрутки. Ответы продолжают выводиться постепенно. Кнопки обычной Главной и обработчики заметок/календаря не менялись.

История беседы **не сохраняется** в файл, локальное хранилище, GitHub или облако; перезагрузка страницы очищает временный контекст. Чтобы явно начать заново без перезагрузки, в режиме «Спросить» напиши `Новый диалог` и подтверди сброс. Временная беседа не записывается в постоянную память. Команды `Запомни: ...`, `Память`, `Забудь 1`, `Очисти память` продолжают работать независимо; очищение беседы **не удаляет** сохранённые факты и наоборот.

Все сетевые запросы идут исключительно на `127.0.0.1`. Сервер принимает не более шести строго чередующихся ролей `user/assistant` в контексте, ограничивает длину и отклоняет попытки подставить `system` или `tool` в историю. Не предназначено для защищённого хранения секретов или персональных данных. Это первый локальный прототип многорепликового диалога, а не облачная синхронизация между устройствами.
