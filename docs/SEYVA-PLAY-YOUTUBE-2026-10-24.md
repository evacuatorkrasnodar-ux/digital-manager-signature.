# SEYVA PLAY · YouTube как часть живого SEYVEO

Дата: 24.10.2026. Репозиторий: `evacuatorkrasnodar-ux/digital-manager-signature.`

## Утверждённое дизайнерское решение

SEYVA PLAY — **не второй видеоплеер и не ещё одно приложение внутри карточки**. Это одна спокойная Black Velvet / White Velvet сцена со знакомым шаром Сэйвы, без новой копии сферы и нижнего дока, без плиток и автоматически начинающейся бесконечной ленты.

Внешний вид:
- Единственная сфера остаётся в существующей верхней позиции `#seyveoCompanion`.
- Только тонкое `SEYVA PLAY`, без английского слогана, пояснений и рекламных подзаголовков.
- Одно большое поле **«Что посмотрим?»** для названия или ссылки. Одна главная кнопка **«Найти»** (для распознанной ссылки — **«Смотреть»**) и тихий **«Пример»**.
- При нажатии появляется один официальный player (16:9, минимум 200×200), с оригинальными кнопками YouTube, субтитрами и полным экраном, насколько доступно устройству.
- Редкие действия (сохранить/продолжить/забыть, внешняя ссылка и юридическая справка) скрыты в **«Ещё»**, которое вообще не видно, пока человек не выбрал или не сохранил видео. Кнопка назад остаётся ниже. Ничто не скрывает органы управления или рекламу YouTube.

Пути входа: из существующего SEYVA MUSIC → «Смотреть видео» или «Источники музыки» → YouTube → «Открыть SEYVA PLAY»; из единственного композера фразами «Сэйви, покажи видео», «открой YouTube», «посмотреть видео». Ссылка вставляется пользователем; по названию PWA пока открывает **настоящую страницу результатов YouTube отдельно по явному нажатию «Найти»** и сохраняет сцену SEYVA PLAY для возвращения. Настоящих результатов поиска **внутри SEYVA PLAY** пока нет, и мы не имитируем их. Для внутреннего каталога нужен YouTube Data API `search.list` через разрешённый провайдер/сервер, с защитой ключа, соблюдением квоты и лицензии. На экране также есть тестовый пример с ID из официальной документации IFrame API; доступность тестового видео не гарантирована.

## Действительная работа

- Только оригинальный разрешённый iframe `https://www.youtube-nocookie.com/embed/<проверенный ID>`, параметры `controls=1`, `playsinline=1`, `autoplay=0`. Никакого стороннего прокси, извлечения аудио, скачивания роликов, скрытия обязательных элементов или автоматических кликов.
- Строгий разбор разрешённых доменов: `youtube.com`, `m.youtube.com`, `music.youtube.com`, `youtube-nocookie.com`, `youtu.be`; ссылка на `watch`, `shorts`, `live`, `embed`; только ID ровно из 11 символов `[A-Za-z0-9_-]`. Запрет произвольных iframe URL и чужих доменов.
- **Ленивый запуск**: при входе на страницу YouTube не запрашивается; даже вставка ссылки не создаёт iframe до явного нажатия «Смотреть». Текстовый запрос открывает официальный поиск на YouTube в новой вкладке — это пока **не** внутренний поиск.
- Во время загрузки видеоплеера оригинальное локальное аудио `#sayviMusicAudio` ставится на паузу, но очередь, файлы и настройки не удаляются.
- При уходе со сцены, сворачивании/блокировке страницы и `pagehide` iframe удаляется: видео прекращается, декодер освобождается. Возвращаясь, пользователь нажимает «Смотреть» заново — **не автоматически**.
- «Сохранить ссылку» в закрытом по умолчанию меню после отдельного касания сохраняет только одно публичное ID в localStorage. **Нет** файла, просмотра историй YouTube, предпочтений без согласия или восстановления таймкода.
- «Открыть на YouTube» — явная внешняя ссылка для случаев, когда регион, автор или платформа не разрешают встраивание. Сэйва сама не переадресует.

## Батарея, CPU и нативная версия

Этот прототип **PWA**, не готовый отдельный нативный iOS/Android-плеер. Видеодекодирование, кодек, системные субтитры и fullscreen делегируются самому браузеру/YouTube. Внутри PWA SEYVEO не контролирует доступность аппаратного декодера и не может обещать фиксированное потребление энергии или изменение качества YouTube без API.

В будущем можно использовать штатные `WKWebView`/`SFSafariViewController` на iOS и `WebView`/`Custom Tabs` на Android **в рамках YouTube API Services Terms и Required Minimum Functionality**, управлять жизненным циклом сцены, сравнивать аппаратное и программное декодирование на устройствах, профилировать память/CPU/температуру, расход батареи на iPhone X и Android. Не подменять официальные потоки собственным недокументированным native decoder, не маскировать YouTube, не отключать рекламу/системные функции.

Проверить на iPhone: встроенный/полноэкранный режим, Play/Pause, разрешения, сторонние cookies/встраивание, возврат в Music без двух потоков, блокировку экрана, маленький дисплей и режим энергосбережения. В PWA **нет гарантированного YouTube-фона**.

Официальные источники:
- https://developers.google.com/youtube/player_parameters
- https://developers.google.com/youtube/terms/required-minimum-functionality
- https://support.google.com/youtube/answer/171780

## Почему модульный код

`index.html` содержит только существующий маршрутизатор, один новый раздел и подключения.
- `assets/seyveo-video-core.js` — чистая проверка ссылок и команд, тестируется без браузера.
- `assets/seyveo-video.js` — ровно один проигрыватель, события, сохранение одного ID, отключение и маршрут.
- `assets/seyveo-video.css` — Black Velvet/White Velvet и размеры на телефоне без тяжёлой графики.
- `tools/test-seyveo-video.cjs` — тесты безопасности, одного iframe, отсутствия автозагрузки, паузы Музыки и выгрузки.

Принцип: не превращать `index.html` в огромный новый монолит. Код старого приложения делить постепенно, не удаляя данные/ключи и не создавая дублирующих контроллеров.

**Статус: рабочая демонстрационная интеграция кода, не проверенная физически на iPhone/Android**. Даже успешные GitHub Actions не подтверждают, что конкретное YouTube-видео доступно в регионе.
