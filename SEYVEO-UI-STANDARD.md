# SEYVEO — ЕДИНЫЙ СТАНДАРТ ИНТЕРФЕЙСА
**Редакция 3.0 · 12 ноября 2026. Действующий дизайн-контракт.**

Этот документ **заменяет все прежние визуальные требования** в репозитории, если они противоречат указанным ниже. Старые стандарты в `docs/` — исторические материалы, не основание для нового оформления. Инженерные, тестовые, юридические и правила безопасности не отменяются.

## 1. Две темы — один интерфейс
- **Белая**: основной этап текущей полировки. **Главный фон экрана строго #FFFFFF (Apple systemBackground)** — чистый белый без грязного серо-зелёного налёта. Для второстепенных плашек/контролов допускается **#F2F2F7 (Apple secondarySystemBackground/systemGray6)**, не для заливки всего экрана. Без цветных фоновых ореолов; текст тёмный почти чёрный.
- **Чёрная**: второй этап, спокойный премиальный чёрный/графит. Не подменять белую тему тёмной.
- Токены материалов у тем разные; геометрия и механика компонентов одинаковые.
- В «Здоровье» белой темы фон задан через `--health-bg:#FFFFFF` и действует единообразно на `#calendarSpaceDialog`, его `::backdrop` и `#svCareScroll`. Токен `--health-inset:#F2F2F7` применяется только к локальным элементам управления. Не возвращать общий `#F8F9FB`.
- `#38383A` остаётся эталонным тёмным графитом для уместных меню/кнопок, но не означает, что каждую кнопку надо залить этим цветом.

## 2. Верхняя шапка — строго единый паттерн
Эталон — предоставленный Apple-подобный экран «Давление»:
- Левая **круглая кнопка 44×44** с тонким шевроном; **заголовок строго по центру экрана** (а не оставшегося пространства); справа круглая 44×44 с действующей контекстной командой, например «+», **если действие реально существует**.
- Шапка низкая, примерно 54–56 px, без толстой рамки, выровнена по safe-area и вырезу камеры.
- На белой теме круглые кнопки нейтральные светло-серые, без толстого борта и тяжёлой тени. Иконки с тонким штрихом ~1.6–1.8 px.
- Дополнительные сегменты/фильтры располагаются отдельно под шапкой **только там, где работают**. Прижатие каждой вкладки к оси, маленький шрифт, лёгкая подложка.

## 3. Док — эталон Apple-подобной нижней панели
- ОДИН работающий док, никакого дубликата поверх него. Основная **низкая горизонтальная матовая капсула** с еле заметным полимерным ободком. **Поиск — отдельная круглая линза** справа, без общей прямоугольной подложки позади них.
- Матовая полупрозрачность и мягкий blur присутствуют, но **никаких толстых стеклянных слоёв**, голубых ореолов, больших теней и фоновой плашки во всю ширину экрана.
- Длина основной капсулы зависит от **числа реальных функций** на конкретном экране. Не растягивать только ради симметрии. Кнопки в ней имеют равный ритм; активный пункт выделяется аккуратным мягким овалом.
- Иконки тонкие, подписи ~10–11 px, ровные отступы. Отдельная лупа — тонкая, аккуратный синий акцент в белой теме.
- Команды и маршруты дока не изменяются молча; **при стилизации одного экрана не перекрашивать доки других экранов**. Вводить каждый следующий раздел отдельно после проверки.
- Сохранять 44×44 px область касания, safe areas, доступность и поведение Safari/PWA. Уменьшается длина панели, но не нажимаемые цели.

## 3.1. Зафиксированный эталон: док «Здоровье» · белая тема (v50)

**Утверждённые параметры не менять без нового скриншота или прямой просьбы пользователя.**
Эталон — присланный скрин Apple «Давление» с «Сводка / Доступ» и отдельным поиском. Замеры сделаны **по скриншоту пользователя, не по редактируемому Figma UI Kit**: доступ к исходному Figma-компоненту отсутствует. Apple HIG подтверждает отдельный поиск, но не публикует точных размеров этого частного варианта:
- https://developer.apple.com/design/human-interface-guidelines/search-fields
- https://developer.apple.com/design/human-interface-guidelines/tab-bars
- https://help.figma.com/hc/en-us/articles/24037833895831-Get-started-with-Apple-s-UI-kit

### Размеры и положение
- На референсе с полезной шириной около **393 pt**: матовая капсула приблизительно **185×60 pt**; отдельная круглая лупа **60×60 pt**; между ними примерно **106–110 pt** пустоты; поля **18–22 pt**. Это **ориентиры по фотографии**, не опубликованные Apple спецификации.
- На экране SEYVEO шириной 390 CSS px ожидается: капсула **183×60 px**, поиск **60×60 px**, зазор около **107 px**, боковые поля примерно **19.5 px**.
- Токены CSS: `--sv-health-capsule:clamp(164px,47vw,190px)`, `--sv-health-search:60px`, `--sv-health-height:60px`, `--sv-health-side:clamp(14px,5vw,22px)`.
- Док центрирован по viewport, ширина `calc(100vw - side - side)`, ограничение `max-width:390px`, `justify-content:space-between` создаёт **широкое свободное место** между капсулой и лупой. Не возвращать фиксированный зазор 24 px.
- В капсуле ровно две равные действующие вкладки («Сводка» / «Доступ»). Каждая — минимум 44 px по ширине, 54 px по высоте; сплошные чёрные иконки сердца и людей **23×23 px**; подписи 10 px.
- Материал обеих поверхностей: **ровное матовое дымчатое серебро** `rgba(211,216,223,.62)` + blur 20 px / saturate 94%. Кайма — натуральный **белый жемчужный пластик, без хрома**: сплошной цвет `rgba(250,249,248,.94)`, толщина 1.5 px; внешний контур `0 0 0 .7px rgba(184,188,198,.24)` и мягкая микротень `0 1px 1.3px rgba(93,102,113,.09)`. **Свет только на отмеченных верхне-левых и нижне-правых коротких дугах**; по сравнению с v61 свет намеренно уменьшен примерно вдвое (толщина SVG-штриха 1.05 вместо 1.7, пиковая прозрачность около .34), чтобы не создавать двойной белый ободок у капсулы и круга поиска. Делать его **исключительно SVG-кривыми со штрихом без заливки**, размещёнными в `::after`; они не должны освещать матовую плоскость даже при отсутствии поддержки CSS mask в Safari. **Запрещены** `conic-gradient` на псевдоэлементе, CSS маски для ограничения света, сияние всего фона, равномерная подсветка рамки, металлические градиенты и хром. Другие доки и чёрную тему не менять.
- Единственный синий акцент — лупа `#007AFF`; работающий общий поиск SEYVEO сохраняется. Сам элемент footer прозрачен, псевдофон отключён.
- **ЖЁСТКАЯ ОБЛАСТЬ ИЗМЕНЕНИЙ:** `:root[data-theme="light"] body dialog#calendarSpaceDialog[data-space="health"] > footer.dock.sv-shared-dock`. Не менять чёрную тему, док главной и другие разделы без прямой просьбы. Не клонировать общий dock DOM; сохранять JS, доступность, нижнюю safe area и Safari.
- При дальнейшей корректировке обновлять этот стандарт, CSS и версию ресурса в `index.html` вместе. Не восстанавливать ранее отклонённые 50/56/58 px высоты, ширину 220 px, зазор 24 px или выпуклое стекло и хромовую окантовку.

## 4. Типографика и смысловой цвет
- Текст тонкий, спокойный, в духе системного шрифта Apple; основной цвет почти чёрный (белая тема) / почти белый (тёмная).
- Жирный вес только для чисел, основного результата и небольших важных заголовков. Убрать лишние крупные заголовки, жирность и многословные пояснения.
- **Цветным делаем текст исключительно по смыслу**: зелёный — нормальный показатель/успех; оранжевый — умеренное отклонение; красный — опасность; синий — интерактивное действие или справка. Не раскрашивать целые карточки, цифры ради красоты и не применять одновременно много акцентов.
- Медицинские оценки остаются информативными, без бесконечно повторяющегося требования обращаться к врачу. Экстренные предупреждения должны сохраняться при опасных симптомах.

## 5. Порядок полировки
1. **Белая тема «Здоровье»** — шапка и док как на скриншотах, визуальная проверка на iPhone, затем остальной экран.
2. Другие белые экраны по одному, после согласования эталона.
3. Чёрная тема на тех же размерах и механике, без переноса тёмных подложек в белую.
4. Убирать конфликтующие CSS-правила в исходном владельце компонента, а не добавлять всё новые слои `!important`.

## 6. Ограничения на изменения
- За пределами явно согласованного экрана **не трогать док** и утверждённые важные элементы.
- При любой правке сохранять обработчики, маршруты, данные, доступы, сбережения пользователя.
- Сначала проверять структуру CSS и источник состояния. Сохранять безопасный откат через историю Git.
- Версии ресурсов обновлять для Safari. Не выдавать проверку в браузере за тест на iPhone.
