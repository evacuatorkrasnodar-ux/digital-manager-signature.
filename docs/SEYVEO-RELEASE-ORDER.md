# SEYVEO — порядок доводки до выпуска

**Утверждено владельцем: 18 октября 2026 года.**
**Статус:** рабочий план; пункт «реализован» не означает «проверен на устройстве».
**Главный принцип:** сначала дизайн и функции → затем сервер → затем интеллект → затем выпуск программы.
**Продукт:** единый «Цифровой управляющий» SEYVEO (LIFE / PRO / MAX).
**Репозиторий:** `evacuatorkrasnodar-ux/digital-manager-signature.`.

## ЭТАП 1 — Дизайн и надёжность интерфейса (текущий)

**Главная является утверждённым эталоном: её композицию, сферу, фирменную анимацию и док без прямого запроса владельца не переделывать.** Выравнивать второстепенные экраны по её системе Black Velvet / White Velvet. Никаких архивных фотографий, лазеров, игровых эффектов или наследованных экранов.

- [ ] Проверить на физическом **iPhone X** и современных экранах: safe-area, вырез камеры, края, вертикальные и горизонтальные переполнения, скролл.
- [ ] Привести второстепенные разделы к одной типографике, стеклянным элементам, радиусам и единым круглым стрелкам / аккуратным закрытиям.
- [ ] Устранить любые скачки дока, сферы, компактного поля и развёрнутого редактора при открытии iOS-клавиатуры.
- [ ] Проверить тёмную Black Velvet и светлую White Velvet, контрастность и системное `prefers-reduced-motion`.
- [ ] Проверить понятность для ребёнка и пожилого человека: крупные зоны касания, читаемый текст, голосовые и экранные подсказки без перегруза.
- [ ] Избавляться от повторяющихся пунктов управления и CSS-наслоений только после проверки зависимостей; не терять функции и пользовательские данные.
- [ ] Реально пройти на телефоне «Первую помощь» и знакомство с владельцем, включая прерывание и повторный запуск.

**Критерий готовности:** основные маршруты и окна не дергаются/не перекрываются на телефоне; обе темы консистентны; урок проходится; нет заметных переполнений, дублей и случайных сбросов данных. Статический тест в GitHub — необходим, но **не достаточен**.

## ЭТАП 2 — Довести функции до рабочего локального MVP (до сервера)

- [ ] **Помощник:** текст, расширенный редактор, голос там, где браузер поддерживает распознавание, история бесед; корректные состояния ошибок и недоступных функций.
- [ ] **Календарь:** создание/изменение/удаление, интервалы, варианты времени, конфликт встреч, локальные сроки и напоминания только при открытом приложении; не обещать системные фоновые push раньше серверного этапа.
- [ ] **Блокнот:** запись, чтение целиком, редактирование, стихи с оригинальными переносами строк, печать/экспорт, без посторонних символов после сканирования.
- [ ] **Мой мир, Забота, Здоровье:** реальные локальные записи и понятная навигация; разграничение личных/рабочих данных; **пока нет шифрования, биометрической защиты или Apple Health-подключения**.
- [ ] **Дела, Картина, Управление, документы:** единая логика поручений и статусов, ясные демо-метки, отсутствие фальшивой автономности и повторяющихся органов управления.
- [ ] **Языковые команды:** явная навигация, черновики записи и события с подтверждением; незнакомые команды не должны молча выполнять действия.
- [ ] **Устойчивость:** сохранение существующих `localStorage` данных, экспорт/импорт с проверкой, работа основных локальных функций без сети.
- [ ] Проверить полный пользовательский путь: первое открытие → знакомство → вопрос → заметка → событие → дело → возврат → повторный запуск PWA.

**Критерий готовности:** любой показанный как «работающий» сценарий реально выполняется без сервера и без ИИ. Недоступные возможности честно помечены. Оставшиеся крупные бизнес-идеи разрешено показывать только как будущее, а не как реальные интеграции. LIFE/PRO/MAX — продуктовая концепция, **не реализованные подписки**.

## ЭТАП 3 — Сервер и аккаунты (после готовности дизайна/локального MVP)

- [ ] Подготовить **локальный тестовый сервер** на имеющемся Windows 11 ПК владельца (i5-12600K, 32 ГБ ОЗУ, ~4 ТБ свободного SSD), без переустановки Windows; рассмотреть WSL2 + контейнеры.
- [ ] Определить серверный API, PostgreSQL, аккаунты, индивидуальную изоляцию пользователей, право отзыва доступа, синхронизацию и восстановление.
- [ ] HTTPS, секреты на сервере, резервные копии **на отдельный носитель**, журналы, обновления и модель угроз для домашних/личных данных.
- [ ] Сначала только локальная сеть и собственные устройства. Внешний доступ — **после** проверки безопасности и с учетом требований к персональным данным.
- [ ] Нагрузочные тесты и аварийное восстановление, прежде чем обещать стабильность сотням и тысячам пользователей.

**Критерий готовности:** сервер безопасно отделяет данные разных людей, восстанавливается после сбоя, не требует оставлять домашний ПК открытым для всей сети без защиты. Сервер не является способом обхода географических или договорных ограничений поставщиков.

## ЭТАП 4 — Настоящий интеллект (после серверной основы)

- [ ] Подключить разрешённого для конкретных регионов и пользователей поставщика модели через серверный адаптер; **никогда не помещать ключ API в PWA/GitHub**.
- [ ] Память, инструменты, локальный/голосовой сценарий, объяснение причины действия, подтверждения, степень доверия, аудит и бюджет запросов.
- [ ] Не выдавать местные правила и демонстрационные ответы за настоящую AI-модель; сообщать об ограничениях модели и сервиса.
- [ ] Запросить официальное разрешение OpenAI, если предполагается обслуживание через OpenAI API пользователей из стран вне опубликованного списка поддерживаемых. VPN/OpenWrt/место сервера не заменяет разрешения.
- [ ] Оценить стоимость на 10, 100 и 1000 активных пользователей; установить лимиты и защиту от чрезмерных расходов.

**Критерий готовности:** интеллект выполняет реальные разрешённые поручения, ошибается безопасно, отделяет пользователей, не раскрывает чужие данные и не зависит от скрытой сетевой схемы.

## ЭТАП 5 — Выпуск (после проверок)

- [ ] Юридическая структура, реальные правообладатели, политика конфиденциальности и условия, магазины, лицензии, платежи и правила регионального доступа.
- [ ] iPhone/iOS: PWA на домашний экран; публикация в App Store — отдельный процесс с возможной нативной оболочкой.
- [ ] Android: PWA, затем публикация в Google Play после технической и юридической проверки.
- [ ] Windows: PWA и возможная публикация через PWABuilder/Microsoft Store.
- [ ] Закрытая бета на нескольких пользователях → корректировки → широкая публикация.
- [ ] Не обещать подписки, синхронизацию, авторассылки и AI-автономность до реализации.

**Критерий готовности:** можно безопасно установить, понятно пользоваться, основные сценарии честно работают, пользователи получают поддержку и могут восстановить свои данные.

## Рабочие правила каждой правки

1. **Одна проблема → точечная правка → синтаксис + `node tools/check-quality.cjs` → проверка интерфейса → обратная связь владельца.**
2. Затронутые файлы, версия ресурса для обновления iOS PWA, коммит и статус проверки указывать явно.
3. Не ломать Главную, сферу, единый док, существующие сохранения и личные записи.
4. Не смешивать понятия **«есть в коде»**, **«проверено технически»**, **«проверено на iPhone»** и **«готово к выпуску»**.
5. Новое предложение не должно сдвигать утверждённые этапы 1–5 без отдельного решения владельца.
