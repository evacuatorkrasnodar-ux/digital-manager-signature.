# SEYVEO Intelligence v1 — единый мозг Феликса

**19 октября 2026 · архитектура предусмотрена целиком. Это НЕ готовый автономный интеллект уровня GPT/Copilot.** Новые способности ещё не включаются от одного появления в списке.

## Суть

Вместо множества несвязанных чат-ботов у нас один Феликс — интерфейс общения SEYVEO. Под ним находятся системные правила, модель Qwen3 через Ollama, будущий GPT через серверный API, модули планирования, память и подключаемые инструменты.

`server/intelligence/architecture.mjs` — единый реестр из 19 областей: интеллект, диалог, память, знания, обучение, бизнес, разработка, документы, календарь, Блокнот, связь и контакты, финансы, налоги, «Мой мир», здоровье, забота, голос, интеграции и безопасность.

Каждая область имеет честный статус:
- `blueprint` — задумана, работающие инструменты **не подключены**;
- `prototype` — отдельные локальные части кода уже есть, но это не готовый пользовательский сервис;
- `server-adapter` — серверные адаптеры предусмотрены, но это не подтверждение доступности облачного API.

**Правило:** `executionEnabled:false` и `automaticAccess:false` у всех областей. Наличие приложения Apple Health, календаря или доступа к GitHub в будущем не означает автоматического права читать или менять данные.

## Как движется просьба

1. Феликс принимает введённый человеком текст, не считывает пользовательские файлы сам.
2. `planAgentTask` из `server/agent/planner.mjs` предлагает намерение и план (без действий).
3. `decide` из `server/hybrid-core.mjs` выбирает предполагаемый маршрут модели.
4. Единая архитектура объединяет предварительный план, область и ограничения.
5. Запрещённые операции, рискованные запросы и приватные области маршрутизируются только в локальный контур. При отсутствии локального ИИ статус `unavailable`, а не скрытый переход в GPT.
6. Облачная модель может быть предложена только при явном разрешении для обычных запросов и реально настроенном сервере. Даже тогда `providerCalled:false`: этот модуль **не делает вызов API**.
7. Любая реальная запись, отправка или платёж требуют будущего отдельного проверенного механизма подтверждений; слова «разрешаю» в чате **не являются разрешением**.

## Как посмотреть уже сегодня

После получения свежей копии GitHub (Node.js 22+):

```powershell
node server/intelligence/inspect.mjs
node server/intelligence/inspect.mjs "Создай встречу завтра"
node --test server/tests/intelligence-architecture.test.mjs
```

Эти команды работают без Qwen, GPT, Tailscale и денег.

В **локальной версии настоящей Главной** (сервер `server/start-real-seyveo.cmd`, `http://127.0.0.1:8790/`) напиши помощнику:

> Филя, покажи возможности

Список появится в существующем пространстве ответа, **без новой страницы или изменения плазмы**. Он отличает подготовленные основы от будущих функций.

API только локального сервера:
- `GET /api/seyveo-intelligence-catalog` — публичный *для локальной страницы* перечень модулей без персональных данных.
- `POST /api/seyveo-intelligence-preview` с JSON `{"message":"Создай встречу завтра"}` — предварительный план **без запуска моделей и инструментов**. Требует правильного Origin и ограничен количеством запросов.

Оба маршрута добавлены в частный, owner-only iPhone-шлюз через Tailscale Serve. Он должен оставаться закрытым; не включать Funnel и проброс портов. Физического теста с iPhone пока не было.

**Публичный GitHub Pages по-прежнему использует демонстрационные ответы; он не превратился в ИИ сам собой.** Главная и плазма не были изменены этой задачей.

## Что действительно работает, а что ещё нет

Работает или частично реализовано в отдельных прототипах: локальная Qwen3 при запущенном Ollama, потоковая текстовая переписка, добровольная локальная память, ранний модуль планов, ограниченная проверка исходников, серверные адаптеры для будущего GPT. В реальном приложении и на разных устройствах это пока не один готовый пользовательский сервис.

Нет в рабочем виде: автономный доступ к почте, календарю, документам, контактам, банку, Apple Health; выполнение кода по запросу пользователя; голосовой разговор полностью без внешних служб; персональная защищённая память всех пользователей; отдельные роли, журнал разрешений, облачная авторизация, подтверждённая GPT-интеграция и масштабируемый backend.

**Следующие этапы:** подключить GPT API законным и безопасным способом на сервере → добавить реальные контролируемые инструменты → сделать единую память с разрешениями → тестировать на iPhone X → проводить независимую оценку безопасности и производительности. Не включать автодействия до появления отдельного механизма разрешений.

Тесты CI: `.github/workflows/agent-core.yml` проверяет маршруты, типы намерений, ограничения и совместимость локального адаптера с исходным `index.html`.

Принцип SEYVEO: **один Феликс, множество будущих навыков, ни одного выдуманного выполненного действия**.
