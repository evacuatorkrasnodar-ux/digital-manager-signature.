# SEYVEO Browser — панель, которая уходит вверх при чтении (native groundwork)

**Утверждённый UX:** сохраняем существующие фирменные вкладки, крестики,
плюс, цвета LED и матовую серую панель. При прокрутке веб-страницы вниз
направление контента идёт вверх — вся верхняя панель (поиск, вкладки и серое
стекло) следует за этим движением и освобождает место. При обратном
движении возвращается; у начала сайта всегда полностью видна.

## Что уже реализовано

- `scroll-chrome.mjs` — простой детерминированный контроллер смещения
  панели, ограниченного её высотой, с обратным ходом и защитой от скачков.
- `BROWSER_SCROLL_BRIDGE_JS` — JavaScript для **настоящего нативного WebView**,
  в котором непосредственно загружена текущая страница: события scroll
  отправляются с ограничением один раз за animation frame.
- `useBrowserChrome.ts` — React hook: `onWebViewMessage`, `injectedJavaScript`,
  `chromeOffsetPx`, `resetChrome`, `setChromeHeight`.
- Тесты `mobile/tests/browser-scroll-chrome.test.mjs`.

## Что ещё не сделано

**Нативный экран браузера пока не интегрирован:** `mobile/App.tsx`
сейчас содержит независимую диагностическую основу. Наша Safari /
GitHub Pages версия по-прежнему использует iframe с чужими сайтами и
**не может надёжно узнавать прокрутку другого домена**, поэтому этот
режим в ней намеренно не включён. Текущий красивый браузер в Safari
сохранён без изменений.

При интеграции Native Browser c `react-native-webview`:

1. Загружать HTTPS-сайт **непосредственно** в WebView, а не во вложенный iframe.
   Для поддержки ещё потребуется добавить зависимость и подготовить native build.
2. Передать `injectedJavaScript` и `onWebViewMessage` от хука в WebView.
   Сообщения от страниц разрешено использовать **только для визуального
   смещения панели**, не для исполнения навигационных/системных команд.
3. Измерить высоту всей поисково-вкладочной панели через `onLayout`
   и передать `setChromeHeight`.
4. Оборачивать **существующие** поиск, вкладки с крестиками, плюс
   и матовое стекло в один `Animated.View`, который смещается по
   `translateY: -chromeOffsetPx`. Движение панели не должно пересоздавать
   WebView и терять открытый URL или положение прокрутки.
5. Вызывать `resetChrome` при смене вкладки, ручном открытии адреса
   или переходе на главную; сохранить нужный доступ к поиску на верхней границе.
6. Тестировать на настоящих iPhone/Android, в том числе длинные сайты,
   страницы с собственными прокручиваемыми контейнерами, формы с клавиатурой,
   быстрые свайпы и системные жесты. Скрипт отслеживает верхний scroll
   документа; сайты с внутренними scroller могут потребовать отдельной логики.

Никаких изменений исходной верстки вкладок в `assets/seyveo-browser.css`
или интерфейса в `assets/seyveo-browser.js` в этом этапе нет.


## 01.11.2026 · решение проблемы сторонних cookies и iframe

На действующей GitHub Pages демоверсии сторонние сайты открываются через
`<iframe sandbox="allow-scripts allow-forms">`. При попытке их скриптов
читать `document.cookie` браузер закономерно выдаёт
`SecurityError: sandboxed and lacks allow-same-origin`; запрет автопостановки
фокуса во вложенном cross-origin фрейме и предупреждения о lazy loading
тоже относятся к ограничениям браузера/сторонних сайтов.
**Не ставить одновременно `allow-scripts` и `allow-same-origin`
без пересмотра модели угроз**, особенно если страница может оказаться
на том же origin, что и SEYVEO. Это не полноценное решение.

Добавлено в **отдельную ветку**, ещё НЕ в рабочее приложение:

- `NativeBrowserViewport.tsx` — родной WKWebView (iOS) /
  Android WebView через `react-native-webview@14.0.1`, версия из
  официальной таблицы Expo SDK 58. Загружает сайт прямо в WebView,
  **не внутри iframe**. Parent обязан сохранить прежнюю геометрию
  верхнего стекла, поисковой строки, вкладок, LED и все пять тем.
- `native-webview-policy.mjs` — HTTPS-only в раннем прототипе,
  запрет локальных IP/localhost, `file:`, `javascript:`, `data:`,
  `blob:`, URL с логином/паролем, нестандартных портов. Реальная защита
  от SSRF/DNS rebinding/опасных веб-страниц потребует отдельного аудита.
- Включены изоляция cookies приложения (`sharedCookiesEnabled=false`),
  запрет сторонних cookies (Android), запрет небезопасных
  HTTP-ресурсов, загрузки локальных файлов. Приватный режим требует
  реального теста поведения хранения на обеих платформах.
- Никакие тексты страницы, cookies, пароли или формы не пересылаются
  через `onMessage` в SEYVEO. Инъекция события прокрутки разрешена
  **только** если родитель передаёт существующий проверяемый мост.
- Отдельный обработчик открытия нового окна `onRequestNewTab`
  принимает только валидированный публичный HTTPS URL.
- Нативный компонент самостоятельный, ещё не встроен в `mobile/App.tsx`.
  Веб-прототип, `assets/seyveo-browser.js`, CSS и пять тем не меняли.
  Для полноценного браузера ещё нужны интеграция вкладок, cookies/логина,
  загрузок, сохранение настроек и тесты с реальными сайтами.
  Некоторые сайты могут блокировать встраивание и в WebView, а логины
  и third-party cookies ограничиваются платформой.

Проверить на устройствах: сайтики с авторизацией, прямые HTTPS,
перенаправления с HTTPS на HTTP, popup, back/forward, скачивание файлов,
приватный режим, скролл панели и работу пяти тем.


## 01.11.2026 · Первый рабочий экран Native Browser

На отдельной ветке создан `NativeBrowserScreen.tsx` и **добавлен вход
«Открыть браузер SEYVEO» в `mobile/App.tsx`**. Это первый
**тестовый нативный экран**, а не выпускная замена фирменной Главной
и не опубликованная отдельная программа.

Проверяемый сценарий в development build iPhone/Android:
1. Нажать «Открыть браузер SEYVEO» на экране мобильной основы.
2. Ввести публичный HTTPS-адрес или вручную запустить поиск в Яндексе.
3. Открыть сайт в нативном WebView — **без iframe sandbox**.
4. Нажать «+» — создать пустую вкладку; переключить/закрыть вкладки.
5. Назад/вперёд/обновление относятся к открытой странице.
6. Нажать ◐ для выбора одной из пяти фирменных тематических палитр
   и дополнительного режима «Автоматически» (пока в памяти экрана).
7. Вернуться стрелкой в диагностическую основу, не меняя её Personal Core.

Ограничения тестового экрана:
- Сессия и выбранная тема пока не сохраняются между перезапусками.
  Переключение вкладки в этой версии пересоздаёт WebView и может
  сбросить историю назад/вперёд; сохранение живых вкладок — следующий этап.
- Палитры — ранняя нативная адаптация пяти утверждённых цветов;
  окончательная точность стекла, LED-подсветки и размеров относительно
  веб-эталона требует визуального QA и не заявляется готовой.
- Нет обработки скачиваний прямо из страницы, полноценного входа
  в сторонние сайты, автосинхронизации или вызова платного ИИ.
  Документы в облако автоматически не передаются.
- Открытие некоторых сайтов/вход через OAuth по-прежнему может
  ограничиваться провайдером и политикой WebView.
- Free-экран показывает **Browser** без надстрочного «+»;
  Browser+ потребует проверенного entitlement в отдельной версии.
- Файлы `assets/seyveo-browser.js`/`.css` на основной ветке
  **не менялись** этим этапом. В PR ещё предстоит проверить native CI,
  затем выполнить реальную сборку и испытания на устройствах.
