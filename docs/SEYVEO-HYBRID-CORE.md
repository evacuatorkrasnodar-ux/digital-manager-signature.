# SEYVEO Intelligence — Hybrid Core (подготовительная версия)

**Начато 19 октября 2026 по новому решению владельца.** Это отдельное ядро, НЕ работающий ИИ в публичном приложении. Действующий дизайн PWA, Главная, док, сфера, localStorage, «Мой мир» и демофильм не изменены.

## Наши три уровня

**SEYVEO Core** — наш собственный код: правила, маршрутизация, разрешения, бюджет, потенциальные инструменты и будущая память. Уже существует как независимый серверный модуль.

**Собственная модель** — предполагаемый self-hosted gpt-oss-20b через Ollama. Саму модель НЕ скачивали и НЕ запускали. Она не является GPT-6.

**GPT-6 через API** — облачная модель для сложных задач. В этой версии реализован серверный адаптер для OpenAI Responses API. Он **выключен по умолчанию**; ключ, счёт и безопасное размещение ещё не настроены. Доступные имена моделей по документации OpenAI на 19.10.2026: `gpt-6-luna`, `gpt-6.1-sol`, `gpt-6-astra`. Это отдельные API-модели, а не «копия» ChatGPT.

## Маршрут

1. Человек передаёт запрос по защищённому каналу (пока только локальный тестовый порт).
2. Core отделяет обычные запросы от чувствительных данных, решений с последствиями и сложных исследований.
3. По умолчанию предпочитается собственная модель (если установлена). Облачная — только для обычного текста **при явном согласии на каждый запрос**.
4. Чувствительные записи и данные о здоровье/контактах не отправляются внешнему провайдеру даже при разрешении облака — требуется отдельная проверенная политика доступа.
5. Формируется текст ответа. **Исполнение действий, отправка писем, изменение календаря, платежи и документы пока запрещены** и не симулируются как реальные.
6. Пока модель недоступна, ядро честно сообщает «не подключено».

## Структура

- `server/hybrid-core.mjs` — правила, классификация, выбор маршрута, ограничения.
- `server/providers.mjs` — адаптер собственного Ollama (`127.0.0.1:11434`) и OpenAI Responses API.
- `server/brain.mjs` — безопасный единый ответ без инструментов.
- `server/http.mjs` — **только локальная разработка**, `127.0.0.1:8787`, токен обязателен; не раскрывать в интернет.
- `server/tests/core.test.mjs` — автономные тесты без сетевых вызовов; `node --test server/tests/*.test.mjs`.

## Запуск локальных тестов

На Windows с Node.js 22:

```powershell
node --test server/tests/*.test.mjs
$env:SEYVEO_DEV_TOKEN = "впиши-здесь-свой-длинный-случайный-секрет-от-24-символов"
node server/http.mjs
```

В другом терминале для проверки статуса:

```powershell
Invoke-RestMethod http://127.0.0.1:8787/health
```

По умолчанию ни одна модель не работает; ответ API на вопрос сообщает о неподключённом интеллекте. Для приватного тестирования локальной модели после её самостоятельной установки в Ollama:

```powershell
$env:SEYVEO_ENABLE_LOCAL = "1"
$env:SEYVEO_LOCAL_MODEL = "gpt-oss:20b"
```

При этом Ollama должен слушать локальный адрес `127.0.0.1:11434`. Эти переменные не устанавливают и не скачивают модель.

**OpenAI API — на следующем этапе:** нужен собственный API-ключ на сервере, доступный платёжный аккаунт и право использования для региона и целевых пользователей. Никаких ключей в клиентском JavaScript, GitHub Pages, публичном репозитории или сообщениях. Для отладки предусмотрены `SEYVEO_ENABLE_CLOUD=1` и `OPENAI_API_KEY` **только в окружении сервера**, а также явное `allowCloud:true` в КАЖДОМ запросе. Приложение GitHub Pages пока не подключено к этому порту.

## Безопасность и стоимость

- Сервис только для локального тестирования, не продакшен. Нет аккаунтов, HTTPS, разграничения пользователей, долговременной памяти, аудита/резервных копий.
- Не открывать порт на роутере, не использовать VPS публично без авторизации, TLS, квот и оценки защиты данных.
- Отправляется только введённый текст, без автоматического чтения заметок, контактов, файлов или истории.
- Ограничены 4000 символов ввода, 700 токенов ответа, 20 запросов в минуту с адреса, HTTP-тело — 12 КБ. Эти пределы снижают риск, но **не гарантируют финансовый лимит**. Бюджеты надо отдельно задать в API-кабинете, прежде чем включать облако.
- Никакого самостоятельного исполнения команд и транзакций, даже в режиме MAX.
- На сервере не создаём данные/историю разговоров; жизненно важные изменения требуют отдельной политики конфиденциальности и согласий.
- Региональные ограничения OpenAI API нельзя обходить VPN или перестановкой сервера. Для российских пользователей нужен поддерживаемый провайдер или официальное разрешение.

## Первый реальный ответ Феликса · защищённая ручная проверка (19.10.2026)

Добавлены `server/verify-gpt6.mjs` и GitHub Actions `SEYVEO · First GPT-6 answer (manual)`.

**Честный статус:** скрипт и ручная кнопка в GitHub готовы, но ещё НЕ было платного запроса к OpenAI. Не утверждать, что GPT-6 подключён, пока проверка не пройдёт с действительным ключом.

**Чтобы однажды запустить вручную (только при законном доступе к OpenAI API):**

1. Самостоятельно создать и настроить OpenAI API-аккаунт с доступным способом оплаты. Сначала установить максимально небольшой лимит использования и оповещения о расходах. Подписка ChatGPT — отдельно от API.
2. В GitHub проекта открыть **Settings → Secrets and variables → Actions → New repository secret**. Создать секрет с именем `OPENAI_API_KEY`. Значение вводить ТОЛЬКО в форму GitHub, не в чат, файлы, Issues или исходный код. Следить, чтобы доступ на запись в репозиторий имели только доверенные люди.
3. Перейти на вкладку **Actions → SEYVEO · First GPT-6 answer (manual) → Run workflow** и выбрать `main`.
4. Открыть журнал ручного запуска. При успехе появится ответ Феликса от модели `gpt-6-luna`. При неуспехе проверить права/квоты/регионы, не раскрывая ключ.
5. По завершении теста при желании отключить или удалить секрет, чтобы не оставлять доступ к платному API.

Без секрета workflow **не может выполнить запрос**. Автоматически на push или расписании НЕ запускается, платежи не совершает самостоятельно. Каждое нажатие `Run workflow` создаёт **один** фиксированный краткий запрос с `store:false`, не пересылает данные из PWA.

**География и условия:** использовать API только при правомерном доступе из поддерживаемых регионов, соблюдая политику провайдера. Запуск из GitHub Actions, другой сервер или VPN не являются разрешением на обслуживание пользователей в неподдерживаемых странах. Для SEYVEO с российскими пользователями заранее планировать альтернативного лицензированного провайдера.

**Важно:** этот smoke test — отдельная серверная проверка, он НЕ подключает живой чат из публичного GitHub Pages. Не вставлять ключ в браузер или PWA. После теста потребуется сервер с TLS, изоляцией аккаунтов, безопасной авторизацией, бюджетным контролем и прозрачными согласиями на облачную обработку личной информации. Существующий простой regex чувствительных слов — лишь защитная эвристика, не гарантия обнаружения персональных данных.
