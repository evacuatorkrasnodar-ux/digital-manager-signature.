# SEYVEO Card Engine — спецификация v1
Дата: 2026-10-30. Статус: архитектура и правила для дальнейшей реализации; не заявлять как уже работающую интеграцию.

## Цель
Один универсальный движок карточек для ONE, RISE, AUTONOM / Enterprise. Не создавать отдельную разметку на каждое письмо и поручение. Существующие сфера, док, Black Velvet HDR и анимация Главной остаются нетронутыми.

## Поток
Адаптер источника → нормализованное событие → дедупликация → правила/классификация → проверка прав → CardModel → приоритизация → визуальный шаблон → действие → подтверждение результата → архив/«Дела»/история.

## Нормализованное событие
eventId, source, sourceRecordId, accountId, workspaceId?, subjectId?, eventType, createdAt, observedAt, title, summary, payloadRef (не секреты в карточке), sensitivity, permissions, correlationId, status.
Идемпотентный ключ: source+accountId+sourceRecordId+eventType+revision.

## CardModel
id, eventId, cardType, title, sourceLabel, actorLabel, contextText, assistantText, proposalText, priority, colorToken, createdAt, expiresAt?, actions[], status, version, privacyLevel, route, auditCorrelationId.
Тексты разбиты на зоны: «Кто и что произошло»; «Суть»; «Сэйви предлагает»; «Действия». Не смешивать реплики пользователя, клиента и помощника.

## Универсальные виды
message, document, task, approval, reminder, calendar, finance, businessInsight, people, care, device, systemNotice. Это шаблоны, не отдельные карточки под каждую ситуацию. Индивидуальные поля и разрешённые действия задаются схемой.
Кнопка входа к Сэйви — единый элемент на любой карточке.
Разрешённые основные действия: «Ответить», «Исполнить», «Подписать», «Подтвердить», «Открыть», «В чат» (для длительного диалога, фото и сложных уточнений).
Показывать не более 1–2 основных действий. «Подробнее» и «В чат» не дублируются. Второстепенные действия в компактном меню или жесте «Позже». Для документа не нагромождать кнопки.

## Состояния
new → shown → action_pending → executing → succeeded → archived.
Дополнительно: deferred, failed, canceled, expired.
Карточка скрывается с Главной ТОЛЬКО после проверенного успеха действия, а не после нажатия.
Для ответа: успешное подтверждение отправки → archived; сбой/офлайн → failed с возможностью повтора. Защита от двойной отправки по actionId/idempotencyKey.
«В чат» не закрывает событие: карточка остаётся, пока задача не выполнена или не отложена.
Действия с финансовыми, правовыми и внешними последствиями требуют явного подтверждения и соответствующих полномочий. Никаких фиктивных отправок/подписей.

## Приоритет
P0 критическое (безопасность, срочное согласование); P1 требует решения; P2 обычное; P3 информационное. Не захватывать экран без необходимости; несколько событий сворачиваются в одну очередь/стопку. Дубли одного события объединяются.

## Режимы
Пилот: предложить → подтвердить → исполнить. Автопилот: только заранее разрешённые, ограниченные по риску операции; чувствительные действия требуют подтверждения независимо от режима.
Enterprise: доступ по роли и workspace; сотрудник не видит закрытые материалы руководителя.

## Developer Inspector
Только в демо/разработческой сборке: event received, rule match, generated card schema, chosen action, execution request, connector acknowledgement, close reason, timestamps, error. Логи с редактированием персональных данных; не показывать токены/пароли/секреты. Кнопки повторного воспроизведения тестовых событий, симуляции ошибки и отсутствия сети.

## Порядок внедрения
1. Реестр типов и валидатор схем, тестовые события.
2. Чистый renderer в текущем прототипе (без изменения Главной).
3. State machine и подтверждение успешного действия.
4. Developer Inspector и тесты на повторные события, сбой отправки и разграничение прав.
5. Адаптеры почты, документов, рабочих чатов, задач и Мой мир.
6. Портирование общего контракта в нативный React Native и подключение к разрешённым интеграциям.

## Приёмочные тесты
- Ответ клиенту успешно отправлен → карточка пропала, запись сохранилась в истории.
- Нажали «Ответить», но отправка не удалась → карточка НЕ пропала.
- Нажали «В чат» → карточка НЕ считается выполненной.
- То же событие получено дважды → одна карточка.
- У документа видно только уместные действия.
- Чужой workspace не получает событие, карточку или содержимое лога.
- Текущие сфера, док, темы и анимация не изменились.


## Утверждённый визуальный стандарт · SEYVEO Silver Flat (09.11.2026)

Применяется **автоматически ко всем типам событий**, которые отображает
`SEYVEO_CARD_ENGINE.renderCard()`, включая галерею Мастерской,
предпросмотр iPhone и учебные карточки на Главной. Для новых семейств
не создаём отдельный HTML/CSS-компонент — они наследуют единый эталон.

- Карточка: фон страницы SEYVEO без дополнительной стеклянной плитки,
  цветной заливки, тяжёлой рамки, объёмных теней или размытия.
  Иерархия: источник → событие → предложение Сэйви → действия.
- Одна основная кнопка: плоский матовый графит `#38383A` в тёмной теме,
  `#E4E7E9` в светлой. Высота видимой капсулы около 32 px;
  область нажатия не меньше 44 px.
- «В чат», «Позже» и прочие дополнительные действия — тихие текстовые
  кнопки с полноценной областью нажатия, без второй капсулы.
- Значок тонкий, без подложки. Семейство события определяет приглушённый
  цветовой акцент; не обесцвечивать все иконки.
- Типографика компактная и контрастная; длинное содержание не обрезать.
  Для сложных действий предусмотрен переход в профильный раздел или чат.
- В Мастерской проверять все зарегистрированные семейства и состояния
  на тёмной и светлой теме. Учебные действия не означают реальную отправку,
  оплату, подпись или успешное завершение.
- Фирменные сфера, док и стеклянные панели чатов не наследуют этот стиль.


### Правило Мастерской · не дублировать советы Сэйви

Если карточка **уже показывает предложение Сэйви** в тексте, нельзя добавлять
рядом кнопку «Сэйви», которая **лишь повторяет это предложение**. Это действует
автоматически для всех карточек Card Engine, в том числе для вновь
зарегистрированных типов. Контракт закреплён в
`assets/seyveo-card-engine.js` (`cardPolicy`, `visibleActions`).

**Исключение:** кнопка Сэйви нужна, если выполняет новое действие:
создаёт черновик, анализирует документ, открывает полноценный чат или
запускает другой понятный сценарий. Такие действия не удалять.

На карточке по умолчанию одна визуально выделенная кнопка с назначением,
не больше; «В чат», «В почту», «Открыть», «Позже» — текстом. У карточки
Почты стандартный набор: основное действие → «В почту» → «Позже».
У документов: основное действие проверки → «Открыть» → «Позже».
В редактировании главное действие может меняться («Сохранить»,
«Разобрать»), но одновременно остаётся только один графитовый акцент.

Мастерская показывает памятку по правилам и автоматически проверяет
каждый зарегистрированный тип на лишние советы, повторяющиеся действия и
несколько основных кнопок. Регрессионная проверка —
`tools/test-card-engine.mjs`. Тестирование кода не заменяет визуальную
проверку iPhone в обеих темах.

Источник оформления: `assets/seyveo-card-system.css`. 
`assets/seyveo-card-studio.css` отвечает за интерфейс Мастерской,
предпросмотр и локальное переключение тем, но не дублирует материал карточек.
Сценарии действий и разрешения остаются в бизнес-логике, не в CSS.
