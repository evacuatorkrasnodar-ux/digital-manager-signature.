# SEYVEO M1 — первый тест на реальном Android

Дата: 20.10.2026. Статус: инструкция, **не подтверждение успешного теста**.

## Что собрали

В GitHub Actions запуск №18 успешно скомпилировал **Android debug APK** и опубликовал ZIP-артефакт `seyveo-mobile-m1-android-debug`. Это нативная диагностическая основа M1, а не полноценный интерфейс и не релиз. В `mobile/package.json` присутствует `expo-dev-client`, а Gradle выполнял `:app:assembleDebug`: APK может требовать Metro/dev server; зелёная сборка CI не доказывает автономного запуска.

## Первое устройство: OPPO A1k (ориентир: Android 9, 2 ГБ RAM)

Версия Android и доступная память должны быть подтверждены на самом телефоне. Совместимость с Expo SDK 58 / React Native 0.88 / включённой новой архитектурой **не проверена**. Ошибка установки на старом Android не означает повреждения файла или потери данных.

## Порядок без реальных секретов

1. Скопировать ZIP артефакта сборки №18 с GitHub, распаковать APK. Не загружать APK с посторонних сайтов.
2. На телефоне проверить версию Android и свободную память; сохранить скриншот.
3. Установить APK. Разрешать установку из неизвестного источника только для выбранного надёжного файлового менеджера, после установки отозвать разрешение.
4. Зафиксировать результат: установлено / не поддерживается / ошибка установки. При ошибке сохранить точный текст или скриншот.
5. При запуске возможно требование Metro: это ожидаемо для development build. Не считать это ошибкой SQLCipher. Для офлайн-тестирования потребуется отдельная самостоятельная сборка со встроенным JS bundle.
6. Если диагностика M1 загрузилась, создать **только пустое тестовое хранилище**, убедиться в сообщении о подтверждённой зашифрованной базе, полностью закрыть и снова открыть приложение. Не вводить документы, пароли или персональные данные.
7. При ошибке или сбое не удалять существующие данные на телефоне; сохранить текст ошибки/скриншот для разбора.

## Критерий следующего этапа

Отдельно проверить автономный старт, настоящее шифрование SQLCipher, повторный доступ к той же тестовой базе и поведение при прерывании. До этого **не считать безопасность доказанной на устройстве**. Главную, док, сферу и веб-прототип не менять во время этих проверок.
