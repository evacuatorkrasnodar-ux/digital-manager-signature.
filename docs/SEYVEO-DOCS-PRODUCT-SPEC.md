# SEYVEO DOCS — продукты, экраны и интерактивный стенд

**Дата:** 8 ноября 2026. **Версия:** 1.0, техническое и дизайнерское ТЗ.

**Главное решение:** мы как разработчики должны видеть и нажимать ВСЕ предусмотренные действия, испытывать их поведение и ловить ошибки ещё до появления сервера и нативной сборки. Поэтому SEYVEO DOCS создаётся в двух прозрачных режимах: **прототип разработчика** и **настоящие возможности пользователя**.

Это не две отдельные программы: одно приложение, одни экраны, один архив и одна Сэйви. Стенд работает в текущей PWA-разработке; перед промышленным выпуском мы отдельно контролируем доступность функций и связываем их с проверенным backend.

## 1. Что делает приложение

Понятный маршрут человека:

**Сканировать → создать / исправить → подписать → напечатать / отправить → сохранить / согласовать.**

Человеку не нужны инструкции по PDF, OCR, ZIP, ЭДО и КЭП до того, как он сам выберет соответствующее действие.

### Структура главного экрана

1. Единая шапка: наша утверждённая стрелка и заголовок «Документы».
2. «Личное / Бизнес» — в прототипе учебное представление; в реальном SEYVEO Business только при серверном членстве, без второй регистрации.
3. Большая лёгкая строка **«Сканировать»**. Подпись: «Фото и страницы → PDF».
4. Четыре компактных действия 2×2: **«Добавить файл», «Создать», «Подписать», «Печать»**. Никаких дублирующих кнопок создания в архиве.
5. **«Мой защищённый архив»** — одна строка, раскрывающая существующий парольный сейф.
6. **«Согласования»** — только бизнес, только по полномочиям; в PWA это явно помеченная учебная модель.
7. **«Работа с документами — с Сэйви»**: «Создать с Сэйви» и «Проверить или исправить», которые ведут в существующий чат и не отправляют файл автоматически.
8. **«Подключения документов»** — один вход в «Управление → Умные подключения → Сервисы», без второго списка серверов, ЭДО и КЭП.

**Низ экрана:** только наш утверждённый глобальный док. Внутри открытого инструмента можно показывать локальный лист действий, но нельзя создавать ещё один док. Контент всегда прокручивается над safe area, в том числе на iPhone X.

## 2. Что разработчики могут нажать уже сейчас

Реальный технический стенд в текущей GitHub Pages PWA включает:

| Кнопка | Что реально происходит | Что НЕ выдаём за готовое |
|---|---|---|
| Сканировать | Системная камера / выбор фото, несколько страниц, локальная подготовка JPEG, настоящий скачиваемый PDF, передача в существующий архив по отдельному нажатию | Автопоиск углов, AI-сканер, OCR, гарантии качества |
| Добавить файл | Действующий системный выбор файла, проверка типа и размера, дальнейший просмотр/архив | Поддержка просмотра каждого формата |
| Создать | Редактируемый текст, несколько учебных шаблонов, настоящий простой DOCX, реальный PDF из страниц текста, отдельное действие «С Сэйви» | Полный Word-редактор, юридическая проверка, гарантия сложной вёрстки |
| Подписать | Холст для пальца/стилуса, очистка, скачивание PNG; при наличии скана — новая PDF-копия с подписью в нижнем углу последней страницы | КЭП, произвольное размещение поверх любого PDF, юридически значимая подпись |
| Печать | Выбор PDF/изображения, открытие файла для системной печати | Автоматическое обнаружение принтеров, утверждение «распечатано» без подтверждения |
| Согласования | Уже существующий интерактивный маршрут, учебные роли, редакции и история | Реальная передача между сотрудниками, серверные права, ЭДО |
| Архив | Действующий локальный AES-GCM-сейф, ручное сохранение и открытие после пароля | Облачное восстановление, настоящий корпоративный сервер |

**Важно:** разработчикам нужен работающий сценарий даже при отсутствии официальной интеграции. Но результат всегда честен. Например, «сохранён PDF» означает реально созданный PDF-файл; «подготовлено к печати» не означает, что принтер уже напечатал.

Пробы с реальными конфиденциальными документами в учебных согласованиях запрещены: там демонстрационные записи без шифрования. Для проверки использовать вымышленные материалы.

## 3. Экран «Умный сканер»

**Вход:** «Документы → Сканировать».

- Разрешение камеры спрашивается только после действия.
- Выбор камеры или галереи; системная отмена не уничтожает ранее собранные страницы.
- До 12 страниц на один локальный PDF в текущей PWA-пробе.
- Показ страниц, нумерация, удаление; реальный результат скачивается или по отдельному согласию передаётся в архив.
- При выходе из раздела или смене роли временные изображения удаляются из памяти, object URLs отзываются.
- Нативный этап: автограницы, коррекция перспективы, поворот, тени, качество, ручная обрезка и OCR, всегда с возможностью «Оригинал».
- Скан удостоверений не является проверкой их подлинности. OCR не может устанавливать юридические факты.

## 4. Экран «Создать»

- Простой редактор для проверки всей цепочки: ввести текст → скачать PDF / Word.
- Шаблоны служат только для разработки и обязательно помечаются учебными.
- Word — настоящий DOCX с редактируемым простым текстом, без обещания сложных таблиц/формул.
- PDF — фиксированные растровые страницы текста; в будущем отдельный качественный текстовый PDF renderer с шрифтами/выделением.
- Новый файл не перезаписывает существующий без согласия.
- «Создать с Сэйви» ведёт в единый чат, а не открывает второй редактор или вторую Сэйви.

## 5. Экран «Подписать»

Строго два типа, нельзя смешивать:

**А. Подпись на экране** — рисунок пальцем/стилусом, очистка, экспорт PNG либо новая PDF-копия скана. В PWA позиция подписи на последней странице фиксированная и прямо указана как ограничение. Нет ложного статуса «официально подписан».

**Б. Официальная электронная подпись** — КЭП/УКЭП, сертификаты, МЧД, аудируемый провайдер, полномочия, точная версия файла. До появления интеграции только переход к настройке «Умные подключения → Сервисы» и честная отметка «Не подключено». Закрытые ключи никогда не извлекать в JS/чат/лог.

## 6. Экран «Печать»

- Пользователь выбирает настоящий PDF или изображение либо использует уже открытый файл.
- Открывается системный просмотр, там человек выбирает «Поделиться → Печать».
- Принтер, бумага, копии и цвет — через реально доступные средства iOS, Android, Windows.
- Никаких выдуманных принтеров и статуса успешной печати только от открытия окна.
- Неподдерживаемый Word печатать через системное приложение или после проверенного преобразования в PDF.

## 7. Экран «Просмотр конкретного документа»

Шапка: имя, формат, дата и фактический статус. Основные действия: «Подписать», «Поделиться», «Ещё».

Меню «Ещё»: «Печать», «Копия», «Сохранить», «Версии», «Сэйви», «Удалить». Для корпоративного документа с разрешениями — «Согласовать», «Вернуть с замечанием», «На подпись», «Отправить контрагенту». Другие роли не получают скрытых возможностей через переключение UI.

Оригинал остаётся нетронутым. Любая подпись, правка или конвертация создаёт копию или новую версию.

## 8. Роли, безопасность и границы

- Один личный аккаунт, независимый личный сейф, отдельные права к конкретной организации. Сервер проверяет **каждое** чтение, экспорт, печать, согласование и отправку корпоративного файла.
- Сотрудник видит только назначенные документы. Руководитель не получает доступ к личным файлам сотрудников.
- PWA-переключатель «роль руководителя / сотрудника» — демонстрация, не аутентификация.
- Файл в Сэйви, письмо, чат, отправку на внешний адрес и принтер передавать только после явного действия пользователя.
- Не загружать документы автоматически на облако и не отправлять тексты в ИИ без согласия.
- Хранить и удалять временные результаты предсказуемо, защищать архив. Safari может очистить локальное хранилище; до появления резервного копирования об этом предупреждать.

## 9. Визуальное оформление

**Стиль:** Apple-inspired iOS 26 Liquid Glass, но со своей идентичностью SEYVEO. Никаких чужих иконок и фирменных графических ресурсов Apple.

- Один заголовок и одна стрелка. Касание от 44×44 px.
- Широкий сканер и четыре равные плитки. Без тяжёлых зелёных заливок, двойных обводок и декоративного объёма.
- Стекло — от общего токен-контракта SEYVEO, нейтральное и полуматовое. Black Velvet в тёмной теме, светлая нейтральная тема с дозированным зелёным акцентом.
- У каждого действия реальные состояния: начало, ожидание, ошибка, отмена, результат, повтор. Учитывать Safari, клавиатуру, VoiceOver, reduced-motion, reduced-transparency.
- Не изменять утверждённый док, сферу, рабочую панель чата, центральный знак и другие экраны во время локальной работы над Docs.

## 10. Этапы и строгая приёмка

**D0 — на текущем PWA:** интерактивные инструменты (камера/фото → PDF, файл, простой DOCX/PDF, рукописный PNG/подписанный скан, печать через ОС), сохранение старого архива, Сэйви и согласований, тесты. Слово «пробная версия» на инструментах обязательно.

**D1 — полировка на реальных iPhone/Android:** правильное размещение на всех размерах экранов, камера/отмена/галерея, обработка больших фотографий, загрузки, печать, клавиатура, подпись пальцем и прокрутка. После каждого исправления визуальная проверка iPhone X.

**D2 — полноценный мобильный сканер:** ручная коррекция и автограницы, OCR, перестановка страниц, пакетное сохранение, доступная обработка без утечки оригиналов.

**D3 — редактор документа:** просмотр и аннотации PDF, перемещение подписи на конкретной странице, улучшенный PDF renderer, DOCX-экспорт, версионирование. Права на копии и экспорт отдельно от просмотра.

**D4 — настоящий бизнес:** Keycloak/OIDC, база организаций, права на каждое действие, серверный архив, согласования между устройствами, события, аудит, резервное копирование.

**D5 — КЭП/ЭДО:** проверенные провайдеры подписи, МЧД, 1С, Диадок/оператор ЭДО, квитанции и подтверждения. Никаких фальшивых статусов.

### Требования к проверке

1. Нажимаются все пять инструментов, работают PDF/Word, сохраняется PNG, можно выбрать документ для печати.
2. На iPhone и Android ничего не прячется за доком и вырезом, панели не скачут. Никаких горизонтальных полос.
3. Личные/деловые файлы, роли и область бизнес-архива не смешиваются.
4. Нет автоматической отправки файлов/подписей/паролей/документов куда-либо.
5. Нет настоящего конфиденциального документа в открытой демобазе согласований.
6. Сбой экспорта не удаляет оригинал. Готовность печати не считается печатью, рисунок подписи не считается КЭП.
7. Смена роли или выход из Docs закрывает локальные файлы/предпросмотры и временные страницы.
8. Отдельная проверка GitHub Actions не заменяет испытания на живом iPhone.
9. В каждой теме сохранены утверждённые геометрия и стекло, без новых глобальных CSS-слоёв.

## 11. Ответственные файлы проекта

- assets/documents-center.js / .css — экран Документы, личный/рабочий контекст, архив и навигация.
- assets/seyveo-docs-studio.js / .css — интерактивные инструменты разработки, без второго дока.
- assets/seyveo-docs-export.js — офлайн-генерация JPG→PDF и текста→DOCX.
- assets/document-vault.js / assets/document-vault-ui.js — существующий локальный шифрованный сейф.
- assets/seyveo-document-flow.js / .css — учебные согласования.
- assets/seyveo-smart-connections.js — единственный центр подключений.
- assets/sayvi-surfaces.js — общая шапка и единый переход назад.
- tools/test-seyveo-documents-screen.cjs и tools/test-seyveo-docs-studio.cjs — проверки рабочего поведения.
- docs/SEYVEO-DOCS-ARCHITECTURE.md — полный технический, правовой и серверный контракт.

**Итог:** разработчики должны видеть ВСЕ проектируемые возможности и проверять каждую. Пользователю промышленной версии нельзя обещать работу того, что ещё не реализовано. Это одно и то же аккуратное приложение, но с прозрачным состоянием готовности.

## 12. Экран просмотра документа — дизайнерский этап 8 ноября 2026

**Готовый визуальный контракт:** при нажатии «Открыть» в локальном архиве или разворачивании выбранного файла отображается одна крупная поверхность с фактическим именем и форматом файла, настоящим предпросмотром PDF/фото/TXT, четырьмя действиями и раскрывающимся меню.

- **Поделиться** — только после прямого нажатия открывается системный диалог с реальным файлом. Это не подтверждение доставки.
- **Печать** — открывается оригинал PDF/изображения для системной печати; интерфейс не создаёт ложный статус «Распечатано». Word/Excel открывается как оригинал во внешнем приложении.
- **Подписать** — изображение JPEG/PNG/WebP передаётся в настоящий уже созданный рукописный редактор. **Произвольный готовый PDF пока не умеем модифицировать**: показывается честное объяснение, нельзя подменять его картинкой или КЭП.
- **Ещё** — «Открыть оригинал», «Сохранить копию», «Сэйви поможет». Передача в Сэйви означает только намерение перейти в чат, без автоматического раскрытия документа.
- Предпросмотр оригинала находится **перед блоком архива**, чтобы он был центром внимания. При закрытии, смене роли и выходе освобождается временный blob URL. Архив и AES-GCM не переписываются.
- Визуально: серебристое матовое стекло только у обрамления и панели инструментов, сам лист остаётся белым, тонкие собственные SVG-иконки; глобальные док, навигация, чат и пять тем остаются без изменений.

Реализация: `assets/seyveo-docs-viewer.js` / `.css`, подключение в `assets/documents-center.js`; интерактивная проверка `tools/test-seyveo-docs-viewer.cjs`. Этот этап — **PWA-дизайн и локальная функция**, не подтверждение полноценной печати/подписи/корпоративной авторизации на устройствах.
