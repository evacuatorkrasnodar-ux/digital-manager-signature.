# SEYVEO Business · подключение сотрудника по приглашению

Статус: **утверждённая продуктовая модель; серверная реализация ещё не подключена**.

## Один человек — два независимых пространства

1. Человек устанавливает SEYVEO и регистрирует **собственный** аккаунт. Личные дела, календарь, Сэйви и личные файлы принадлежат ему.
2. До приглашения у пользователя ONE **нет постоянной вкладки «Работа»**. Личные функции уже работают. Нейтральный вход «Управление → Приглашения» позволяет принять рабочее или семейное приглашение.
3. Руководитель назначает кадровика / администратора команды. Организация импортирует список работников из CSV/Excel или, после подключения, из 1С/HRIS. Сэйви предлагает сопоставление сотрудников с отделами, филиалами, должностями и типовыми разрешениями; назначение утверждает уполномоченный человек.
4. Компания создаёт индивидуальное приглашение для сотрудника. В приглашении фиксируются организация, филиал, должность, рабочая роль и перечень доступа (или утверждённый шаблон), срок действия и приглашающий.
5. После входа в персональную учётную запись приложение показывает **одно и то же входящее приглашение** карточкой на Главной и сообщением в чате Сэйви. Только если подтверждён контакт или открыт защищённый индивидуальный канал; иначе до проверки личности нельзя показывать чужие кадровые данные.
6. Сэйви коротко поясняет: «Вас приглашает компания. Должность — кассир, магазин №2. Подключиться?». Сотрудник видит **принять / отклонить**; без принудительной длинной анкеты.
7. Принятие запускает **серверную** проверку одноразового токена, срока действия, личности получателя, статуса организации и актуальности назначенных прав. При необходимости — повторная проверка телефона/почты или кадровое подтверждение.
8. Только успешный ответ сервера создаёт членство в организации и активирует рабочую вкладку **«Дела · Календарь · Работа»**. Рабочие чаты, задания, график, документы и инструменты загружаются исключительно по подтверждённым правам.
9. Увольнение, отзыв приглашения, перевод или изменение должности меняют рабочие полномочия **на сервере**. Личное пространство SEYVEO не удаляется и не передаётся работодателю.

## Одноразовый код как простой способ подключения

**Альтернативный вход к тому же приглашению**, а не отдельная система ролей: «Управление → Приглашения → Ввести код». Человек сам решает, использовать персональную ссылку/QR, приглашение от Сэйви или код. Все варианты приводят к одной серверной записи `organization_invitation` и одной операции активации.

Код генерируется сервером для конкретного приглашения, имеет криптографически стойкую случайность, одноразовость и короткий срок жизни. Сервер хранит только защищённый проверочный хеш, проверяет подтверждённый канал получателя, ограничивает попытки, блокирует перебор и повторное использование, пишет аудит. Ввод кода **не заменяет подтверждение личности**. Нельзя выдавать всем 200 работникам единый код для автоматической активации: такой код может только подать заявку на проверку кадровиком.

Сценарий без лишних кнопок: ввести код → увидеть проверенное приглашение и разрешения → явно принять → сервер создаёт членство → открывается рабочий кабинет внутри той же программы. Неверный/истёкший/уже использованный код даёт безопасную ошибку без раскрытия сведений о компании или адресате. **Никакая локальная демо-кнопка не выдаёт настоящие права.**

## Удобство массового подключения

- Для сети на 200 сотрудников: один импорт и авто-предложение структур по точкам/отделам, групповое создание приглашений и уведомление о неподтверждённых.
- Один шаблон «Кассир магазина №2» применяется ко всем соответствующим людям; исключения и выдача повышенных прав требуют отдельного подтверждения.
- Руководитель назначает кадровика/администраторов организации и руководителей подразделений. Они управляют только в рамках делегированной области.
- Подписку оплачивает организация; рабочие места выдаются из её тарифа. Сотрудник не должен покупать отдельную Business-подписку, чтобы принять приглашение.

## Технический контракт для сервера

`organization_invitation`:
- `id` (не секретный идентификатор приглашения), `organization_id`, `recipient_contact_hash` или подтверждённый `recipient_user_id`;
- `branch_id`, `department_id`, `position_id`, `role_template_id`, `issuer_user_id`;
- `status = pending | accepted | rejected | revoked | expired`, `expires_at`, `created_at`, `accepted_at`;
- хеш одноразового секретного токена, который **не помещается в логи и клиентский localStorage**.

Серверные действия:
- `GET /me/work/invitations`: только приглашения, доступные проверенной личности;
- `POST /me/work/invitations/:id/accept`: атомарная проверка приглашения и создание членства; защита от повторного использования/гонок, журналирование;
- `POST /me/work/invitations/:id/decline`: явный отказ;
- `GET /me/work/memberships`: активные рабочие пространства;
- `POST /organizations/:id/invitations/batch`: только для уполномоченного кадровика/администратора, с предварительным просмотром и подтверждением;
- `POST /organizations/:id/memberships/:id/revoke`: отзыв доступа с немедленной инвалидизацией рабочих токенов.

Для Главной и чата Сэйви использовать **единый источник уведомлений** по `invitation.id` — без дублирующих запросов, кнопок и ложных статусов. Клиент не вправе доверять самоназначенной должности, флагу локального предпросмотра или тексту ссылки для выдачи прав.

## Границы текущего прототипа

На GitHub Pages сейчас только **учебное представление Елены**. Роли `window.SEYVEO_PREVIEW`, демонстрационные поручения/чаты и переключение между кабинетами — **не аутентификация** и не доступ реального сотрудника. Ни одна локальная кнопка «Принять» не должна выдавать разрешения, пока не появится серверный контур. Учебный кабинет сохранить доступным для тестирования, отдельно обозначив его статус. Настоящие приглашения, проверенные уведомления на Главной и у Сэйви, массовые рассылки и реальная синхронизация пока **не реализованы**.
