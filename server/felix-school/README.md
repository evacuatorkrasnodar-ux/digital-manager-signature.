# Школа Феликса · SEYVEO

**Статус:** первый урок подготовлен. Это начало обучения поведению, а не обученные веса Qwen3.

В текущей версии изменены системные инструкции `safeInstruction` в `server/hybrid-core.mjs`: Феликс должен понимать распространённые опечатки и неверную раскладку, не придираться к грамотности и сохранять строки стихов, имена и смысл при явной просьбе исправить текст. Эти правила применятся к локальному Феликсу **после обновления файлов из GitHub и перезапуска**; старый запущенный процесс их не получит автоматически.

## Материалы

- `persona.mjs` — работающие в системном промпте правила характера Феликса: полезность, инициатива и умеренный добрый юмор.
- `persona-lessons.jsonl` — ещё 12 новых синтетических примеров характера (не запускают обучение весов).
- `../tests/felix-persona.test.mjs` — автоматическая проверка общих инструкций и ограничений.
- [SEYVEO-FELIX-PERSONA.md](../../docs/SEYVEO-FELIX-PERSONA.md) — полное описание и ручная проверка.
- `lessons.jsonl` — 12 **искусственно написанных** примеров правильного общения: помощь бизнесу, опечатки, приватность, сохранение строк и честность о выполненных действиях. Они **не отправляются автоматически модели** и не меняют её веса.
- `eval-cases.json` — 6 отдельных проверочных вопросов. Не включать их в обучающий датасет, чтобы видеть настоящее улучшение, а не заученные ответы.
- `evaluate.mjs` — диагностическая проверка через **локальный Ollama 127.0.0.1:11434**, только по явной команде `--live`. Никаких ключей или платных API, результаты не записываются на диск.
- `../tests/felix-school.test.mjs` — автоматические проверки данных и того, что режим по умолчанию не делает сетевых вызовов.

Из корня **свежего ZIP** репозитория:

```powershell
node --test server/tests/felix-school.test.mjs
node server/felix-school/evaluate.mjs
```

Обе команды не обращаются к модели. При работающем Ollama, **если хочешь проверить реальные ответы**, запусти:

```powershell
node server/felix-school/evaluate.mjs --live --limit=3
```

По умолчанию будет не более трёх тестовых вопросов. Для всех шести: `--limit=6`. Тесты могут быть медленными на CPU. Если Ollama недоступна, команда завершится ошибкой, ничего не меняя.

Результаты `PASS` и `REVIEW` — **грубые текстовые признаки**, а не оценка интеллекта человеком. Реально исправленный текст может быть лучше или хуже того, что зафиксировали регулярные выражения. Не включать ответ Феликса в тренировочный набор без ручной проверки.

## Как двигаться к настоящему дообучению

1. Сначала проверить текущее поведение по отдельным тестам, записать ошибки **без личных данных**.
2. Улучшать системную инструкцию и безопасную локальную базу знаний. Ничего автоматически не «запоминать» от людей.
3. Собрать значительно больше качественных, проверенных диалогов из разрешённых или синтетических данных, разбить по категориям, оставить независимый контрольный набор.
4. Если это всё ещё необходимо, дообучить **подходящую базовую Qwen3** с помощью LoRA/QLoRA на совместимом GPU. Модель, формат, лицензия, объём памяти и итоговый экспорт требуют отдельной проверки. Компьютер без дискретной видеокарты лучше оставить для запуска готовой модели, а не для тяжёлой тренировки.
5. Развернуть кандидата **отдельно** от работающего Феликса, сравнить качество и скорость с исходной моделью; возвращаться к старой версии при ухудшении. Не подменять рабочую модель автоматически.

Обучающие материалы **не включают личные переписки, данные здоровья, контакты, пароли, документы или секреты**. Их нельзя собирать от пользователей без отдельного информированного согласия. Не публиковать настоящий пользовательский датасет в GitHub.

Нельзя считать модель «обученной» только потому, что мы записали уроки: сейчас изменена системная инструкция, а файл уроков является заготовкой для будущей работы.

## Пакет № 2 — подготовлен без запуска Ollama

По решению владельца SEYVEO **сначала собираем учебные пакеты, а затем вместе проводим один большой живой экзамен**, не прерывая разработку после каждого примера.

- `lessons-batch2.jsonl`: ещё **32 собственноручно составленных синтетических диалога**, без реальных переписок и персональных данных. Направления: бизнес-логика, полезное несогласие, программирование, точность дат, документы, контакты, денежная безопасность, медицинская серьёзность, умеренный юмор, честность о возможностях и согласие.
- `exam-batch2.json`: **20 отдельных контрольных вопросов**, не скопированных из уроков. Нужны для независимой проверки поведения, а не для обучения.
- `evaluate.mjs` теперь принимает только фиксированные наборы `--suite=baseline` (6 прежних вопросов) или `--suite=batch2` (20 новых). Произвольный путь к файлам подсунуть нельзя.
- `../tests/felix-batch2.test.mjs`: проверка данных, независимости экзамена и отсутствия сетевых вызовов по умолчанию.
- Добавлен запуск проверок пакета № 2 в `.github/workflows/agent-core.yml`.

**Когда придёт время общего экзамена**, открой терминал в корне свежей копии репозитория и выполни сначала тесты структуры (Ollama не нужен):

```powershell
node --test server/tests/felix-school.test.mjs server/tests/felix-batch2.test.mjs server/tests/felix-persona.test.mjs
node server/felix-school/evaluate.mjs --suite=batch2 --limit=20
```

Последняя команда — только предварительный показ: **без `--live` обращений к модели нет**.

При работающем Ollama и установленной модели для настоящего экзамена:

```powershell
node server/felix-school/evaluate.mjs --live --suite=baseline --limit=6
node server/felix-school/evaluate.mjs --live --suite=batch2 --limit=20
```

Это **26 модельных вопросов**, могут выполняться долго на i5-12600K без видеокарты. Не запускать экзамен без желания владельца.

**Очень важная граница:** сохранение `.jsonl` в GitHub само по себе **не обучает веса Qwen3**, и учебные примеры `lessons-batch2.jsonl` пока не добавляются автоматически в запросы к модели. Их цель — накопить корректный набор для будущего отдельного LoRA/QLoRA обучения на подходящем GPU. Немедленное влияние на ответ имеет лишь уже подключённая системная инструкция Феликса (через `safeInstruction`). Контрольные вопросы нельзя использовать как тренировочные данные.

`PASS` и `REVIEW` проверяют лишь **слабые лексические признаки**. Например, «предлагаю проверить расходы» может не совпасть с шаблоном, а ошибочный ответ иногда совпадёт случайно. Поэтому финальный вывод о качестве делаем **вручную**, сравнивая полезность, безопасность, точность и последовательность диалога. Отсутствие ошибок в этих тестах не доказывает, что модель стала умнее.

Суммарно подготовлено: **56 учебных примеров** (12 основных + 12 характера + 32 новых) и **26 проверочных вопросов** (6 старых диагностических + 20 новых независимых). Важно: среди старых 6 вопросов один совпадает с первым учебным набором, поэтому старый набор не считается полностью независимым экзаменом; новая двадцатка не совпадает ни с одним учебным запросом. **Настоящее дообучение весов и живое тестирование Ollama ещё не проводились.**
