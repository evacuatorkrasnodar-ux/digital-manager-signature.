# SEYVEO Browser — панель, которая уходит вверх при чтении (native groundwork)

**Утверждённый UX:** сохраняем существующие фирменные вкладки, крестики,
плюс, цвета LED и матовую серую панель. При прокрутке веб-страницы вниз
направление контента идёт вверх — вся верхняя панель (поиск, вкладки и серое
стекло) следует за этим движением и освобождает место. При обратном
движении возвращается; у начала сайта всегда полностью видна.

## Что уже реализовано

- `scroll-chrome.mjs` — простой детерминированный контроллер смещения
  панели, ограниченного её высотой, с обратным ходом и защитой от скачков.
- `BROWSER_SCROLL_BRIDGE_JS` — JavaScript для **настоящего нативного WebView**,
  в котором непосредственно загружена текущая страница: события scroll
  отправляются с ограничением один раз за animation frame.
- `useBrowserChrome.ts` — React hook: `onWebViewMessage`, `injectedJavaScript`,
  `chromeOffsetPx`, `resetChrome`, `setChromeHeight`.
- Тесты `mobile/tests/browser-scroll-chrome.test.mjs`.

## Что ещё не сделано

**Нативный экран браузера пока не интегрирован:** `mobile/App.tsx`
сейчас содержит независимую диагностическую основу. Наша Safari /
GitHub Pages версия по-прежнему использует iframe с чужими сайтами и
**не может надёжно узнавать прокрутку другого домена**, поэтому этот
режим в ней намеренно не включён. Текущий красивый браузер в Safari
сохранён без изменений.

При интеграции Native Browser c `react-native-webview`:

1. Загружать HTTPS-сайт **непосредственно** в WebView, а не во вложенный iframe.
   Для поддержки ещё потребуется добавить зависимость и подготовить native build.
2. Передать `injectedJavaScript` и `onWebViewMessage` от хука в WebView.
   Сообщения от страниц разрешено использовать **только для визуального
   смещения панели**, не для исполнения навигационных/системных команд.
3. Измерить высоту всей поисково-вкладочной панели через `onLayout`
   и передать `setChromeHeight`.
4. Оборачивать **существующие** поиск, вкладки с крестиками, плюс
   и матовое стекло в один `Animated.View`, который смещается по
   `translateY: -chromeOffsetPx`. Движение панели не должно пересоздавать
   WebView и терять открытый URL или положение прокрутки.
5. Вызывать `resetChrome` при смене вкладки, ручном открытии адреса
   или переходе на главную; сохранить нужный доступ к поиску на верхней границе.
6. Тестировать на настоящих iPhone/Android, в том числе длинные сайты,
   страницы с собственными прокручиваемыми контейнерами, формы с клавиатурой,
   быстрые свайпы и системные жесты. Скрипт отслеживает верхний scroll
   документа; сайты с внутренними scroller могут потребовать отдельной логики.

Никаких изменений исходной верстки вкладок в `assets/seyveo-browser.css`
или интерфейса в `assets/seyveo-browser.js` в этом этапе нет.
