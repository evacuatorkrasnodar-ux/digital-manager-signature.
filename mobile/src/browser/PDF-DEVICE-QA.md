# SEYVEO Browser — проверка настоящего PDF на телефоне

**Статус:** сценарий подготовлен, но пока **не выполнен на реальном
iPhone или Android**. GitHub Actions проверяет JavaScript/TypeScript, но
не доказывает работу платформенного PDFKit/PDFBox в телефоне.

## Что уже подключено в коде

- Мобильная основа `mobile/App.tsx` открывает `NativeBrowserScreen`.
- В нижнем доке есть «Загрузки»: там же `BrowserDownloadsPanel`.
- На тестовом экране доступна ссылка на общедоступный PDF W3C:
  `https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf`.
  Сначала кнопка **«Проверить настоящий PDF · тест»** только подставляет
  ссылку; только второе нажатие **«Скачать»** начинает загрузку.
- У скачанного документа появляется **«✦ Сэйви, посмотри»**.
- Чтение текста проводится на устройстве, до 10 МБ и 8 страниц, с
  согласия пользователя. Для PDF-сканов пока нет OCR.
- Объяснение внешним ИИ по умолчанию **отключено**: не имеется ни
  настроенного OIDC-провайдера, ни публичного авторизующего HTTPS
  сервера. Локальный `server/ai-mail-server.mjs` — только
  loopback-инструмент разработчика с отдельным dev token. Никогда не
  добавлять этот dev token в mobile и не разворачивать этот dev server
  как публичный API.

## Ручной тест (development build, не Expo Go)

1. На телефоне с установленной нативной сборкой открыть приложение
   SEYVEO -> **Открыть браузер SEYVEO**.
2. В нижней панели нажать **«Загрузки»** (стрелка вниз), затем
   **«Проверить настоящий PDF · тест»**.
3. Проверить, что URL подставился, но сетевого запроса ещё нет.
   Нажать **«Скачать»**, дождаться записи в локальный список.
4. Открыть файл; затем нажать **«Сэйви, посмотри»** и разрешить локальное
   чтение. Проверить, что устройство реально извлекло текст PDF,
   показывается заголовок «Просмотр файла» и число прочитанных страниц.
5. Нажать «Объяснить с Сэйви»: пока без подтверждённой OAuth-сессии
   функция должна быть выключена, а не отправлять текст на сервер.
6. Перезагрузить приложение, убедиться, что файл остался в локальном
   списке. Удалить его; проверить, что исчез после перезапуска.
7. Протестировать в отдельности скан без текстового слоя, парольный PDF,
   файл больше 10 МБ, прерывание загрузки, отключение сети,
   открытие на iOS и Android.
8. После подключения настоящего Identity Provider и HTTPS API:
   проверить неверный/просроченный токен (нет запроса к ИИ), согласие
   на передачу только просмотренного фрагмента, отказ от согласия
   (нет запроса), структурированное объяснение и отсутствие его
   автоматической синхронизации.

**Обязательная доработка для production:** OIDC issuer/client config,
проверка подписи и прав access token на сервере, доверенный HTTPS
backend, подтверждение App/Universal Links, настройка хранения и
ротации токенов, пер-пользовательский rate limit, UI входа/выхода,
реальные device tests и аудит приватных данных.

## Что показывает CI

`npm test`, `tsc --noEmit`, Android/iOS JS bundles; это не
полноценные нативные установочные APK/IPA и не проверка реального PDF.
