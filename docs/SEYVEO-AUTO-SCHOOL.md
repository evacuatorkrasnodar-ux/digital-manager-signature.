# SEYVEO Auto School — ИИ учит ИИ (30.10.2026)

Это самостоятельная автоматическая локальная школа SEYVEO для будущих нативных iOS и Android приложений. Никакой разработки PWA в этом модуле.


## Версия 2 · восемь экзаменов и видимый дневник (30.10.2026)

Теперь обычный запуск через start-auto-school.cmd проводит **восемь попыток экзамена**: письма, поручения, календарь, документы, бизнес-арифметика, личные данные, общение и умные карточки.

В окне школы видно:
- текущую тему и номер урока;
- реальный сгенерированный вопрос;
- эталон ответа учителя и критерии;
- ответ Сэйви;
- оценку из пяти и объяснение экзаменатора;
- причину отклонения, если задание недопустимо.

После завершения автоматически сохраняются три файла **только на компьютере**:
- %LOCALAPPDATA%\SEYVEO\auto-school\last-session.html — красивый визуальный дневник в Black Velvet, открывается в браузере при успешном запуске через CMD;
- %LOCALAPPDATA%\SEYVEO\auto-school\last-session.txt — полный текстовый дневник;
- %LOCALAPPDATA%\SEYVEO\auto-school\last-session.json — структурированные результаты для будущей статистики.

Имеющийся экспериментальный набор experimental-sft.jsonl продолжает содержать только те примеры, где Сэйви не справилась, а эталон учителя прошёл автоматическую проверку. Если все восемь заданий пройдены, **ноль новых учебных примеров — нормальный результат**, но вопросы и ответы всё равно попадут в дневник. Если модель учителя сгенерировала невалидный пример, он будет отклонён; восемь попыток не гарантируют восемь содержательных экзаменов.

Запуск вручную:

    node server/seyveo-auto-school/run.mjs --count=8

На компьютере без видеокарты восемь экзаменов могут занимать ощутимое время: учитель и экзаменатор последовательно вызывают Ollama. Программа пишет состояние после каждого экзамена в консоль; отчёт сохраняется в конце полной сессии.

Важно: это **оценки ИИ-экзаменатора**, а не независимая экспертиза. Они не доказывают, что новая Сэйви действительно стала умнее. Текущий процесс **не дообучает веса**, не обновляет ответную модель в приложении и не переносит пользовательскую память в обучающий набор. Одобрение выпуска новой версии после отдельного тестирования остаётся обязательным.

## Проверка по первому настоящему дневнику — 30 октября

В первом полном отчёте 8 попыток, 6 оценок «сдала», 1 кандидат (календарь) и 1 отклонённый образец (умные карточки). Найдена серьёзная ошибка: для 150 единиц по 250 при себестоимости 120 учитель записал прибыль 22 500, хотя правильный расчёт — 19 500. Экзаменатор поставил 5/5 ошибочному эталону.

С текущего обновления добавлен **независимый арифметический контроль без ИИ** для простых бизнес-задач формата «количество × цена; количество × (цена − себестоимость)». Он не допустит неверный эталон в обучение даже при ошибочной оценке экзаменатора. Если формат сложнее или числа нельзя надёжно разобрать, система консервативно отклоняет пример — это пока не универсальная финансовая проверка. Проверка ученицы тоже ограничивает оценку, если результаты не сходятся.

Также скорректированы подсказки учителю, ученице и экзаменатору: Сэйви должна отвечать **естественно, коротко, без фраз о лаборатории**, уточнять только нужное, а экзаменатор должен учитывать лишнюю многословность и не занижать балл календаря за уместные дополнительные сведения. Нейросети всё ещё могут нарушать такие подсказки, поэтому потребуется смотреть новые отчёты.

Изменения влияют только на **новые** запуски после GitHub Pull. Старый last-session.html не меняется сам по себе. Веса модели не обучаются.

## Что происходит автоматически

1. Учитель Qwen3 8B создаёт полностью вымышленную задачу с эталонным ответом.
2. Экзаменатор проверяет эталон по критериям.
3. Ученица Qwen3 4B решает задачу.
4. Экзаменатор оценивает ответ ученицы; если эталон получил 5/5, а ученица не справилась, появляется новый *экспериментальный кандидат*.
5. Кандидаты складываются в отдельный набор SFT/LoRA, чтобы позже обучить компактную модель на CUDA GPU.

Без участия человека проходит подготовка материалов. Оценка учителя пока делается самой Qwen3 8B с другим запросом, поэтому независимость экзаменатора ограничена. Это фильтр, не доказательство точности.

Система НЕ читает личные чаты, письма, документы, память, реквизиты пользователей. НЕ отправляет запросы в облако, НЕ изменяет код приложения, НЕ выпускает обновления самостоятельно и НЕ меняет веса модели на этом шаге. Новые примеры НЕ попадают автоматически в рабочую память Сэйви. Грубый фильтр личных сведений не является гарантией обезличивания — публиковать эти примеры без дополнительной проверки нельзя.

## Запуск на Windows

Нужны Node.js и работающая Ollama. Один раз скачайте модели:

    ollama pull qwen3:8b
    ollama pull qwen3:4b-instruct

Команды из корня репозитория:

    node server/seyveo-auto-school/run.mjs --check
    node server/seyveo-auto-school/run.mjs --dry-run
    node server/seyveo-auto-school/run.mjs --count=8

Или дважды нажмите server/seyveo-auto-school/start-auto-school.cmd.

На i5 без видеокарты 8B будет работать заметно медленнее маленьких моделей. Школе нужен только Ollama, сервер сайта не нужен.

Результаты хранятся только на компьютере:

    %LOCALAPPDATA%\SEYVEO\auto-school\state.json
    %LOCALAPPDATA%\SEYVEO\auto-school\experimental-sft.jsonl

Они не попадают в GitHub. Школа защищается файлом running.lock от одновременных запусков. После аварийного выключения файл блокировки может потребовать ручного удаления, если приложение точно больше не выполняется.

## Автоматическое расписание

После успешного ручного запуска включить ежедневную Windows задачу можно отдельной командой:

    powershell -ExecutionPolicy Bypass -File server\seyveo-auto-school\install-daily.ps1

Скрипт обязательно спрашивает YES перед установкой. После согласия Windows Task Scheduler будет запускать 8 задач каждый день в 02:30, если ПК включён и Ollama доступна.

Отключить: Планировщик заданий Windows -> SEYVEO Auto School -> Отключить.

Это работа локальной программы, а не работа ChatGPT в фоне.

## Реальное дообучение весов — следующий этап

Подготовлен отдельный GPU-скрипт на Hugging Face TRL + QLoRA:

    python server/seyveo-auto-school/train_gpu_lora.py
    python server/seyveo-auto-school/train_gpu_lora.py --train

Он требует минимум 100 синтетических примеров и совместимый NVIDIA CUDA GPU, PyTorch, TRL, PEFT, Transformers, Datasets и BitsAndBytes. Без флага --train модель не запускает обучение. При обучении создаёт экспериментальный LoRA-адаптер для Qwen/Qwen3-4B-Instruct-2507; выбранную базовую модель необходимо проверить на совместимость с используемой в Ollama.

GPU-этап пока НЕ протестирован. Данные учителя могут содержать ошибки, а случайное разделение на train/test НЕ заменяет независимого экзамена. Перед выпуском нужна отдельная оценка качества и безопасности. Автоматических публикаций нет.

## Проверки

    node --test server/seyveo-auto-school/auto-school.test.mjs
    python -m py_compile server/seyveo-auto-school/train_gpu_lora.py

Тесты не вызывают Ollama и не записывают настоящие данные пользователя.

## Файлы

- server/seyveo-auto-school/core.mjs — сценарии, контроль, отбор
- server/seyveo-auto-school/ollama.mjs — локальные Ollama-вызовы
- server/seyveo-auto-school/store.mjs — набор экспериментальных примеров
- server/seyveo-auto-school/run.mjs — автономная учебная сессия
- server/seyveo-auto-school/start-auto-school.cmd — запуск одним нажатием
- server/seyveo-auto-school/install-daily.ps1 — добровольное ежедневное расписание
- server/seyveo-auto-school/train_gpu_lora.py — отдельное реальное GPU-дообучение
- server/seyveo-auto-school/auto-school.test.mjs — тесты без внешней сети

Следующий необходимый шаг — независимый экзаменатор и отдельные holdout-задания. Только после доказанного улучшения можно готовить выпуск новой версии Сэйви. Личная память человека никогда автоматически не передаётся в общую учебную систему.
