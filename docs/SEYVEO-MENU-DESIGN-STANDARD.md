# SEYVEO — Единый дизайн-стандарт всплывающих меню
Статус: утверждено, 21 ноября 2026 г.  
Приоритет: белая тема; затем чёрная.  
Визуальный референс: меню **«Стиль бумаги»** в Блокноте.  
Принцип: **чётко читаемое меню на непрозрачной поверхности; полупрозрачность только у доков и навигационных капсул.**

## 1. Типы поверхностей
| Элемент | Материал | Назначение |
|---|---|---|
| Небольшое меню настроек, выбора инструментов, действий и помощи Сэйви | Плотный непрозрачный | Чтение, настройка, выбор, подтверждение |
| Основной док, горизонтальная/вертикальная навигационная капсула | Тонкий полуматовый материал SEYVEO | Быстрый доступ, без длинного текста |
| Собственный экран редактора, холст, лист | Фон самого экрана | Нет дополнительной накладывающейся «рамки» |
| Системная палитра iOS/Android или браузера | Системный интерфейс | Не имитировать вторую палитру и не пытаться неустойчиво переопределять нативный контрол |

**Никогда:** не использовать `backdrop-filter` или размытую полупрозрачную заливку для меню, которое расположено поверх текста, фотографии или рукописных штрихов. Через такие меню рисунок не должен просвечивать.

## 2. Утверждённые токены
### Белая тема
- Поверхность меню: `#FCFCFD`, **alpha 1**, без backdrop-blur и стеклянных слоёв.
- Основной текст: `#252A33`; вторичный: `#747B86`.
- Рамка: `1px solid rgba(130,139,150,.20)`.
- Тень: `0 12px 34px rgba(25,33,45,.16)` и сдержанный внутренний блик `inset 0 1px 0 #FFF`.
- Кнопка/ячейка: `#F3F4F6`, рамка `#E9EBEF`; выбранная: `#E6E9ED`, рамка `#D8DDE4`.
- Никаких цветных заливок для обычных меню. Для опасных действий допускается только осмысленный красный акцент.

### Чёрная тема
- Поверхность: `#292B30`, **alpha 1**, без backdrop-blur.
- Текст: `#F3F3F6`; вторичный: `#B8BDC6`.
- Кнопка/ячейка: `#373A41`; выбранная: `#4B4F58`.
- Рамка: `1px solid rgba(255,255,255,.14)`.
- Тень: `0 14px 34px rgba(0,0,0,.35)`.

## 3. Геометрия
- Радиус внешнего меню: **20 px** (допустимо 18–20 для узких контекстных меню).
- Внутренний отступ: **14 px** (минимум 12).
- Шаг между кнопками: **8 px**; между разделами 12–16 px.
- Радиус кнопок: **11–12 px**.
- Высота интерактивной зоны: ориентир **44 px**, минимум 40 px для компактного меню, без тесных подписей.
- Ширина: только по содержимому, например `min(300px, calc(100vw - 32px))`; меню не растягивать до ширины экрана без необходимости.
- Заголовок: 14–15 px, вес 600; основной текст и кнопки 13–14 px, вес 400–500; пояснение 11–12 px.
- Тёмные, аккуратные векторные иконки с единой линией около 1.6–1.7, по центру на общей базовой линии; не смешивать крупные грубые и тонкие иконки.
- Выбор из 3 элементов — три равные карточки; из 4/6/8 — симметричная сетка 2 колонки, если содержание позволяет. Избегать случайной полноширинной последней кнопки.
- Выравнивание, safe-area, доступная прокрутка на iPhone 10, Android и компьютере. Без обрезанного содержимого и появления меню за границей экрана.

## 4. Поведение
- Открывается от одной существующей кнопки; не дублирует постоянные инструменты в других панелях.
- Одновременно открыто не более одного всплывающего меню внутри редактора.
- Нажатие вне меню закрывает его без случайного мазка на холсте.
- Кнопки выполняют реальные действия. Недоступная возможность явно отмечается, а не имитирует результат.
- Выбранное состояние выражено материалом/вдавливанием, не лишней галочкой и не отдельной цветной плашкой.
- `aria-expanded`, `aria-pressed`, названия действий, фокус клавиатуры и состояния disabled синхронизированы с логикой.
- Хранилище пользовательских штрихов, Undo/Redo, OCR и настройки кистей НЕ изменять при унификации стиля.

## 5. Область применения
Последовательно привести под единый материал:
1. Блокнот: «Перо для заметки», «Стиль бумаги», параметры рукописного ввода, выбор `Aa`, вложения.
2. Рисование: выбор инструмента/кисти, настройки, цвета и градиенты (не создавать дубль системной палитры).
3. Сэйви: панель творческих действий и контекстные предложения.
4. Остальные разделы SEYVEO: документы, почта, календарь, карточки, рабочие действия — только собственные поповеры, а не системные контролы.

Текущая реализация **уже** переопределяет фон `#svSmartInkPicker` как непрозрачный в `assets/seyveo-notebook-context-actions.css`. В `assets/seyveo-notebook-editor-v3.css` остаются ранние полупрозрачные объявления. При рефакторинге убрать дубли и привести компоненты к одним переменным, не наслаивая бесконечные `!important`-патчи.

## 6. Рекомендованный способ внедрения
Завести единый набор CSS custom properties:
```css
:root[data-theme="light"] {
  --sv-menu-bg: #fcfcfd;
  --sv-menu-text: #252a33;
  --sv-menu-secondary: #747b86;
  --sv-menu-border: 1px solid rgba(130,139,150,.20);
  --sv-menu-shadow: 0 12px 34px rgba(25,33,45,.16), inset 0 1px 0 #fff;
  --sv-menu-item: #f3f4f6;
  --sv-menu-item-selected: #e6e9ed;
  --sv-menu-radius: 20px;
}
:root[data-theme="dark"] {
  --sv-menu-bg: #292b30;
  --sv-menu-text: #f3f3f6;
  --sv-menu-secondary: #b8bdc6;
  --sv-menu-border: 1px solid rgba(255,255,255,.14);
  --sv-menu-shadow: 0 14px 34px rgba(0,0,0,.35);
  --sv-menu-item: #373a41;
  --sv-menu-item-selected: #4b4f58;
  --sv-menu-radius: 20px;
}
```
Базовый класс меню использовать повторно, а позиционирование оставлять ответственностью конкретного экрана. Не переоформлять док этими токенами.

## 7. Проверка перед утверждением любого меню
- На насыщенном разноцветном рисунке **ничего не видно сквозь меню**, все подписи читаются.
- Меню пера и бумаги имеют одинаковый материал, рамку, радиус и типографику.
- Нет двойных рамок, сторонних затемнений, прыжков размера и наложений.
- Белая и чёрная темы, Safari на iPhone, Android и ПК проверены визуально и функционально.
- В текущем GitHub-репозитории наличие этого ТЗ **не означает, что весь проект уже переведён на стандарт**. Внедрение проверять отдельно по каждому экрану.

**Правило SEYVEO:** «Стекло — для навигации. Плотный материал — для чтения и выбора».
