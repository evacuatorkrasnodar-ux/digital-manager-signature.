# SEYVEO · Recruiting / Агентство подбора (04.11.2026)

## Цель
Полноценный центр найма для руководителя без кадрового отдела и для HR-команды. Сэйви сопровождает вакансию, отклики, собеседование, проверку профессиональных требований, согласование решения и адаптацию. Источник истины для внешних статусов — **официально подключённая платформа**, а не предположения ассистента.

## Текущий код
- `assets/seyveo-recruitment.js` + `.css`: локальные вакансии, ручные отклики, проверяемые критерии, этапы и объяснение Сэйви.
- `index.html` → `#seyveoRecruitment`; область перемещается текущим `preparePeopleContent()` в вкладку «Подбор».
- `assets/seyveo-hr-demo.js`: отдельное учебное интервью, не внешний рекрутинг.
- Данные центра в `localStorage: seyveo-recruiting-local-v1`. Не серверные аккаунты, не межустройственная синхронизация и не полноценное защищённое хранилище персональных данных. Для реальных кандидатов нужна серверная реализация и политика хранения. Локальные сценарии проверять на обезличенных тестовых данных.

## hh.ru — официальная интеграция (ещё не подключена)
Документация: https://dev.hh.ru/ и https://api.hh.ru/openapi/redoc

1. Зарегистрировать SEYVEO как приложение разработчика и согласовать доступ работодателя к API. Не собирать пароль от hh.ru в чате.
2. OAuth2 authorization code + безопасное хранение/ротация токена **на сервере**; привязка работодателя, организация, роли. Никогда не помещать токен в фронтенд/localStorage.
3. Раздел «Источники»: подключено / требуется авторизация / доступ ограничен / ошибка. Проверять платные методы и доступ к базе резюме отдельно.
4. Публикация и редактирование вакансии: сначала черновик Сэйви, затем явное подтверждение руководителем, только после этого запрос API.
5. Отклики работодателя: получать официальные коллекции откликов/приглашений по вакансии, сохранять внешние ID и timestamp, делать идемпотентную синхронизацию и дедупликацию. По возможности официальные события, иначе ограниченный расписанием polling с backoff, без обхода лимитов.
6. Карточка «Сэйви: новый кандидат на вакансию ...»: создавать **только** из фактически полученного нового разрешённого отклика; ссылка открывает конкретного кандидата. Уведомления по отдельному согласию.
7. Оценка: сравнение с заранее заданными рабочими критериями; «что кандидат указал», «что не подтверждено», «что спросить». Никаких психологических домыслов, защищённых признаков, общего балла пригодности или автоматического отказа.
8. Переписка, приглашение, смена статуса, отказ/приём: проверять разрешённые действия API и требовать подтверждения ответственного человека. Не утверждать, что действия применены, пока не получен успешный ответ внешней системы.
9. Аудит, авторизация, доступ по роли, согласия, срок хранения и удаление/экспорт персональных данных обязательны до рабочего запуска. Схему персональных данных и трансграничные потоки проверить юридически перед выходом на рынок.

## Другие платформы
Подключать через независимые адаптеры `RecruitmentProvider`: `authorize`, `listVacancies`, `listApplications`, `getCandidate`, `allowedActions`, `updateApplication`. Только договорные API. Не обещать доступ к любой площадке автоматически, не парсить закрытые резюме.

## Критерии приёмки следующего этапа
- Источник не подключён: никаких вымышленных «новых кандидатов».
- Подключённый аккаунт: один фактический отклик → одна карточка Сэйви → одна запись кандидата с источником и временем.
- Ошибка/нет доступа/лимит: честная причина и возможность безопасно повторить.
- Руководитель видит основания и пробелы; может исправить критерии и принять собственное решение.
- Сотрудник не видит неразрешённые персональные данные кандидатов.
- Смена статуса в SEYVEO только после подтверждённого успешного действия источника.
