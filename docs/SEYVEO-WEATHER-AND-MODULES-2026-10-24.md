# SEYVEO · Живая погода и здоровая архитектура кода

Дата: 24 октября 2026 г. · Реализация в действующем PWA-репозитории `digital-manager-signature.`.

## Что работает в прототипе

Погода возникает в **одном пространстве Главной**, под сценой Сэйвы — не новая карточка, стеклянный слой, док или сфера. Чтобы включить, человек один раз касается «Показать погоду» и подтверждает системное разрешение геолокации. До этого **нет** обращения к погодному API и запроса GPS.

После согласия сохранены только приблизительные координаты, округлённые до двух знаков после запятой (обычно около 1 км, зависит от широты). Оригинальные точные координаты не сохраняются и не посылаются поставщику. Прогноз обновляется при входе на активную страницу и примерно раз в 45 минут, а не фоном в закрытом PWA. Показываются текущая модельная температура, погодный код, атмосферное давление, высокая вероятность осадков, локальное время прогноза и обязательная видимая ссылка на источник. Если данных нет — **нет выдуманной погоды**.

В Настройках погоды можно заново запросить расположение или отключить погоду, удалив сохранённые координаты. Никакого скрытого отслеживания и никаких медицинских измерений внутри погодного модуля.

## Погода и Здоровье

В прототипе общая, не персонализированная информация появляется только при экстремальных значениях: сильная жара, мороз, сильный ветер. Она аккуратно отображается на Главной и в действующем разделе «Здоровье». Погода **не измеряет артериальное давление**, не ставит диагноз и не советует изменять лекарства. Пользовательские показатели давления/пульса остаются в прежнем локальном хранении: новая погодная функция их не считывает, не объединяет и не передаёт провайдеру.

Медицинская основа: American Heart Association, научное заявление 2026 года *Nonoptimal Temperature and Cardiovascular Health*. Холод и жара могут сопровождаться изменениями гемодинамики и сердечно-сосудистыми рисками, но индивидуальная реакция неодинакова. В будущем персональные пояснения допустимы только при отдельном согласии, корректных измерениях и клинически проверенных алгоритмах.

## Точность и лицензии

Оценочный источник — **Open-Meteo Best Match**. Он применяет подходящие метеомодели для региона, но не способен гарантировать «самый точный прогноз» в каждом месте и в каждый час. Свежесть показана временем модели, источник — ссылкой рядом с результатом. Нет фиктивного статуса «суперточный» или несуществующей метеостанции.

**Ограничение:** открытый бесплатный API Open-Meteo предназначен для некоммерческого прототипирования. Для реального коммерческого SEYVEO нужен лицензионный контракт / платный ключ на `customer-api.open-meteo.com` или другой согласованный провайдер. Перед релизом: сравнить прогнозы и наблюдения по конкретным регионам, точность по фактической погоде, задержку обновления, покрытие РФ, официальные штормовые предупреждения, стоимость и fallback. Ключи хранить на защищённом сервере, не в PWA.

Источник API: https://open-meteo.com/en/docs и https://open-meteo.com/en/pricing.
Медицинское заявление: https://professional.heart.org/en/science-news/nonoptimal-temperature-and-cardiovascular-health/top-things-to-know.

## Почему не один огромный index.html

Проверенный `index.html` исторически вырос примерно до **265 КБ**: HTML, часть CSS, встроенный управляющий код. Это увеличивает риск случайных перекрытий и сложных исправлений. Большой файл *не запрещён* технически, но архитектурно плох как единственное место для всей логики.

Правило для нового функционала: одно назначение = один маленький модуль. **Живая погода** уже разделена так:

| Файл | Ответственность |
| --- | --- |
| `assets/weather-core.js` | чистая валидация, перевод условий, простые осторожные сигналы |
| `assets/weather-provider.js` | граница внешнего API, проверка координат, получение проверяемых данных |
| `assets/weather-presence.js` | пользовательское согласие, обновления, отключение, одна текстовая строка и здоровье |
| `assets/weather-ink.css` | Black/White Velvet, адаптивность, отсутствие рамок и анимационного шума |
| `tools/test-weather.cjs` | регрессия форматов, приватности, источников, сигналов и одного дока |

`index.html` только подключает CSS и JS. Мы не добавили туда ещё одно огромное тело функций.

План безопасного дробления прежнего монолита:
1. Составить карту старых inline-стилей, маршрутов и зависимостей; определить один источник истины для каждого поведения.
2. Вынести сначала **чистые функции** без DOM/хранилища, зафиксировав их тестами.
3. Вынести инфраструктуру маршрутов/событий и рендеринга **без изменения DOM ID, ключей localStorage и поведения iPhone**.
4. Вынести разросшиеся визуальные правила из HTML, убрать дублирующиеся селекторы, сохранить токены Black Velvet и систему доступности.
5. Переносить по одному модулю с проверкой GitHub Actions и физического iPhone X/Android. Нельзя одним коммитом без тестов удалить половину приложения.

Никакая оценка скриптами не равна визуальной приёмке на телефоне. Не объявлять истинным «погода в фоне» при закрытом браузере: для гарантированных фоновых обновлений и уведомлений потребуется нативное приложение с разрешениями ОС и серверной инфраструктурой.

## Приёмка

- До нажатия «Показать погоду» браузер **не просит** место, сеть погоды не вызывается.
- После разрешения показывает актуальную пометку источника; после запрета — честную ошибку.
- Отключение удаляет координаты; здоровье и личные данные не отправляются метеосервису.
- Тёмная/светлая темы, ориентации, 320–430 px, iPhone X safe-area и отсутствие наложения на док/клавиатуру.
- В «Здоровье» только общие осторожные сигналы, никаких автоматических «у вас давление 150».
- При отсутствии интернета нет ложного прогноза и вымышленных предупреждений.
- Проверить бюджет сети, доступность фокусом/VoiceOver и поведение внутри установленной PWA.
