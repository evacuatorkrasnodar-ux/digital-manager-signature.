# SEYVEO · Феликс проверяет бизнес-расчёты

**19 октября 2026 · Business Math v0.1.** Первый самостоятельный вычислительный инструмент для будущего цифрового управляющего, без модели и внешних сервисов.

## Зачем это нужно

Раньше наша «Школа Феликса» лишь показывала образцы ответов и проверяла отдельные слова в ответах Qwen. Это не доказывает, что модель умеет считать. Теперь мы можем независимо пересчитать девять простых бизнес-показателей и сравнить числовое утверждение модели с формулой.

**Честный статус:** модуль готов как отдельная библиотека `server/intelligence/business-math.mjs` и не подключён к интерфейсу переписки. Феликс пока **не вызывает его самостоятельно**; подключать к чату и реальным бизнес-данным будем после проверки безопасного пользовательского интерфейса и прав. Веса Qwen3 не менялись.

## Поддерживаемые показатели

| Ключ показателя | Расчёт |
| --- | --- |
| `revenue` | Цена за единицу × количество |
| `profit-before-tax` | Выручка − переменные расходы − постоянные расходы |
| `gross-margin` | (Цена − себестоимость) / цена × 100% |
| `markup` | (Цена − себестоимость) / себестоимость × 100% |
| `break-even-orders` | Округлённые вверх постоянные расходы / вклад заказа (цена − переменные затраты) |
| `conversion` | Заказы / посетители × 100% |
| `cost-per-lead` | Расходы на рекламу / количество заявок |
| `customer-acquisition-cost` | Расходы на рекламу / количество новых платящих клиентов |
| `order-growth` | (Текущие заказы − предыдущие заказы) / предыдущие заказы × 100% |

У этих показателей есть **явные допущения**. Например, прибыль «до налогов» учитывает только те расходы, которые переданы в функцию; это не готовый бухгалтерский отчёт. Для конверсии предполагается не более одного учитываемого заказа на уникального посетителя в заданной воронке, а для CAC — корректное распределение затрат по источнику привлечения.

Все деньги в аргументах задаются в рублях строкой или числом с не более чем двумя знаками после точки (`'125.50'`). Внутри деньги пересчитываются в целые копейки. Результат всегда содержит формулу, единицы измерения (`RUB`, `percent`, `orders`), точную строку результата и предупреждение о непроверенных исходных данных.

Если цена/себестоимость приводят к делению на ноль, если заказ не покрывает переменные издержки или если нет исходных заказов для сравнения роста, возвращается **`not-calculable`**, а не догадка. При неизвестном показателе, запрещённых полях и недопустимых размерах входа возвращается ошибка. Важная особенность: **для сравнения результата нейросети вызывающий код должен сам передать данные расчёта и её числовое утверждение**. Инструмент не извлекает суммы из свободного текста и не угадывает их.

## Проверка без Qwen / интернета

Когда решим провести общие испытания, в обновлённой копии GitHub запустить:

```powershell
node --test server/tests/business-math.test.mjs
node server/intelligence/business-math-demo.mjs
```

В демонстрации только синтетические значения — никаких персональных финансов. Например, модель может заявить, что из 600 посетителей и 18 заказов конверсия составляет 10%. Независимый расчёт покажет **3%** и `verdict:'mismatch'`.

Использование отдельной библиотеки из программного кода:

```js
import {calculateBusiness,verifyBusinessClaim} from './server/intelligence/business-math.mjs';

calculateBusiness('conversion',{visitors:600,orders:18});
// status: 'calculated', exact: '3.00', unit: 'percent'

verifyBusinessClaim('conversion',{visitors:600,orders:18},'10');
// verdict: 'mismatch', expected: '3.00', claimed: '10.00'
```

Тесты `server/tests/business-math.test.mjs` покрывают девять формул, отрицательные значения, округление в точке безубыточности, деление на ноль, отклонение опасных/неполных полей и отсутствие внешней сети. Они включены в `.github/workflows/agent-core.yml`; **результат полного запуска GitHub Actions на момент написания документа ещё не проверен**.

## Безопасность

Модуль не получает ключи, контактные данные, файлы, CRM, банковские счета. Не делает сетевые вызовы, платежи, изменение записей или запланированную работу. Не даёт инвестиционных или налоговых гарантий. Только чистая арифметика по **явно переданным** значениям; флаг `inputFactsVerified:false` напоминает, что даже правильный расчёт по неверным цифрам не становится фактом.

Задача следующего этапа: изолированный инструментарий, который распознаёт намерение «посчитать», показывает исходные значения пользователю для проверки и только после согласия применяет детерминированный калькулятор. Не включать доступ к реальным финансам только потому, что появилась функция расчёта.
